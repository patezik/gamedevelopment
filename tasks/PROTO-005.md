# PROTO-005 — Исход необратимого действия после переподключения: признак совершённого обвинения

## Описание

Шлюз отправляет `action.result` только по текущему сокету и не кладёт его в буфер возобновления
(protocol.md §7: буфер хранит `event` и `view.update`). Если соединение оборвалось после того, как
сервер исполнил `accuse` с `confirm: true`, но до доставки `action.result`, клиент не может узнать
исход: при прощённом ложном обвинении снимок после переподключения не содержит `ending`, а
`PlayerView` никак не отражает совершённое обвинение. Номер `stateVersion` растёт от любого
действия и не связан с конкретным запросом.

В GDT-009 клиент сохраняет неизвестный исход по `sessionId` на время работы клиента и блокирует
новое обвинение в этой игре. Если прежний запрос не дошёл до сервера, игрок может потерять
возможность обвинить до конца сессии.

## Цель

После переподключения клиент получает исход своего запроса или безопасно завершает его повтором
с тем же идентификатором операции.

## Scope

- Рекомендуемый подход для ADR — устойчивый ID операции для `confirm: true` и серверный исход,
  коррелированный с парой «игровая сессия и ID операции». Этот ID сохраняется при переподключении
  и повторе того же `CaseFile`. Привязка к операции и ограничение по роли проверяются сервером.
- Сервер атомарно связывает выполнение с записью исхода и защищает операцию от повторного
  исполнения. Повтор с тем же ID получает сохранённый исход или понимает, что операция ещё в
  работе. ADR задаёт срок и область хранения исходов, а также поведение для устаревшего ID и
  повтора с другим `CaseFile`.
- ADR описывает замену desktop-пира, запрос старого сокета, исполняющийся с задержкой, и
  `resync` после выпадения истории. Исход должен быть доступен при полной пересинхронизации.
  Один буфер `action.result` покрывает только `resume` в пределах удержанной истории.
- Общий счётчик рассмотренных обвинений годится как дополнительный сигнал. Его рост может
  относиться к другой операции, а равенство в снимке оставляет возможность позднего исполнения.
- ADR (AGENTS.md §7), protocol.md §6–§7, фикстуры и контрактные тесты. `AccusationLedger`
  разрешает UNKNOWN на основании коррелированного исхода.

## Ожидаемый результат

После обрыва во время `confirm: true` клиент может восстановить исход операции. Повтор этой
операции в пределах срока и области хранения, принятых в ADR, защищён от повторного исполнения.

## Критерии приёмки

- [x] ADR принят, контракт и фикстуры обновлены.
- [x] Живые тесты покрывают потерю результата после исполнения, запрос в очереди при замене пира
      и повтор операции до исполнения. Одно обвинение с тем же ID исполняется не более одного раза.
- [x] После `resume` и `resync` с вытесненной историей клиент получает исход именно своего ID.
- [x] В представлениях нет полей истины (контрактный тест).
- [x] `npm run tasks:check` и проверки CI зелёные.
