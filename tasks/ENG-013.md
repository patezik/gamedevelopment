# ENG-013 — Цели мотива для обвинения: кого игрок может указать в motive(c, v)

## Описание

`accuse` принимает мотив как `ClaimRef` вида `motive(<обвиняемый>,<против кого>)`
(investigation-model.md §6), и `evaluateAccusation` засчитывает его только при точном совпадении
с установленным утверждением. Второй аргумент в правилах — обычно жертва инцидента. `PlayerView`
не называет жертв: клиент знает лишь персонажей из `caseBoard` (персоны интереса, отметки,
говорящие), `presentCharacters` и собеседника. Экран обвинения GDT-009 предлагает выбрать цель
мотива из этих персонажей; если жертва среди них не встречалась, доказать мотив, а значит и
получить концовку `solved`, через интерфейс нельзя.

Подтверждено на реальной проекции `tiny-manor` (ревью PR #123): клиент мог выбрать `ch_bursar`, но
не `ch_owner`; тот же набор улик в тесте ядра даёт `solved`, а через интерфейс без мотива —
`partial`.

Решение владельца по [OQ-22](../docs/planning/open-questions.md): игрок выбирает цель мотива
из известных ему пострадавших. Реализация ведётся отдельно от GDT-009.

## Цель

Игрок может сформулировать любое утверждение о мотиве, которое способен доказать найденными
уликами, не получая из представления ни виновных, ни решения.

## Scope

- По решению OQ-22: добавить в `PlayerView` (например, в `caseBoard`) известных игроку
  пострадавших или иной список допустимых целей мотива; без раскрытия истины.
- Контрактный тест: поле не содержит виновных и не зависит от `culpritIds`.
- Обновить экран обвинения GDT-009, если формат выбора меняется.

## Out of Scope

- Правила вывода мотива (OQ-20), изменение `evaluateAccusation`.
