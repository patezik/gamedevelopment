# CNT-013 — Точки осмотра для физических следов в locations.json

## Описание

Улика физического следа находится осмотром точки с `id`, равным шаблону следа (`ruleFor`, EvidenceGen).
В `sanatorium_winter/locations.json` таких точек не было: `missing_substance` и другие `kind: physical` из
`trace-rules.json` игрок найти не мог, поэтому `means` был недоказуем на настоящей генерации (OQ-26 из
отчёта SRV-012).

## Цель

Для каждого физического следа есть точка осмотра в локации, где след может появиться; игрок находит его
осмотром, сквозное решение возможно.

## Scope

- Точки осмотра с `id` = шаблону следа во всех подходящих локациях `sanatorium_winter`.
- Тексты точек (канонический и два варианта) в `text/ru/locations.json`.
- Тест, что у каждого физического шаблона есть точка, а клики следов seed 1, 2, 3, 6 достижимы.

## Out of Scope

- Изменение правил дедукции, проверок валидатора и `ruleFor`.
- Новые шаблоны следов.

Физические следы достижимы осмотром.

## Критерии приёмки

- [x] Для каждого физического шаблона из `trace-rules.json` есть точка осмотра с `id` = шаблону.
- [x] Seed 1, 2, 3, 6 проходят шлюз; каждая улика-точка лежит в локации с такой точкой.
- [x] Ни одна проверка валидатора не ослаблена.
- [ ] `npm run tasks:check` и проверки CI зелёные.

- [x] На реальном сгенерированном деле санатория штатный GameEngine с портами SRV-012 позволяет осмотреть обязательную физическую улику через доступную игроку точку.
  Подтверждено `apps/server/src/qr/physical-clue-path.test.ts`. Сквозной результат с обеими проверками подтверждается в [INT-002](INT-002.md).
