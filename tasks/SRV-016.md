# SRV-016 — Удаление seed из публичного списка сохранений

## Описание

`GET /api/v1/saves` без аутентификации возвращал `SaveSummary.seed` сразу после первого
сохранённого действия. Тест SRV-007 проверял это поведение. В штатном
процессе маршрут появится вместе с [SRV-015](SRV-015.md). Для итогового разбора ENG-012 раскрывает
seed только в `PlayerView.ending`.

Владелец подтвердил по OQ-40, что список должен исключать seed всех сохранений.
[Решение владельца](https://github.com/patezik/gamedevelopment/issues/189#issuecomment-7198636361) ·
[ADR 0023](../docs/architecture/adr/0023-save-list-seed.md)

## Цель

Список сохранений даёт выбрать прохождение по метаданным. Seed остаётся на сервере
для восстановления дела и доступен игроку после завершения в `EndingView.seed`.

## Scope

- Убрать seed из публичного ответа `GET /api/v1/saves` для всех записей, включая
  завершённые игры и старые сохранения. Список использует метаданные независимо от исхода игры.
- Сохранить поля списка `saveId`, `scenarioId`, `updatedAt` и `gameTime`.
- Синхронизировать `SaveSummary` и `SaveList` из PROTO-006, фикстуру ответа и сгенерированную JSON Schema.
- Оставить seed в файле сохранения для загрузки и replay.

## Out of Scope

- Регистрация маршрута в штатном сервере (SRV-015) и атомарность
  `POST /api/v1/saves/:saveId/load` (SRV-014).
- Формат сохранения на диске, алгоритм загрузки и replay, диагностика, UI и `EndingView`.

## Зависимости

- [SRV-007](SRV-007.md) — существующие список и загрузка сохранений.

## Затрагиваемые модули

- `packages/protocol/src/rest.ts`, `fixtures/rest/saves.json`, `schemas/rest-save-list.json`
- `packages/protocol/test/rest.test.ts`
- REST-документация, ADR 0023 и запись OQ-40

## Ожидаемый результат

К моменту подключения маршрута в SRV-015 публичный список содержит только метаданные.

## Критерии приёмки

- [x] После сохранения активной игры запись в `GET /api/v1/saves` сохраняет метаданные
  списка. Поле `seed` отсутствует.
- [x] Старое незавершённое сохранение не раскрывает seed в списке и загружается с прежним хешем.
- [x] Запись завершённой игры использует те же четыре поля. Список строится без replay.
- [x] При отсутствии файла метаданных `gameTime` равен `null`. Строгая схема отклоняет `seed`.
- [x] `npm run tasks:check` и проверки CI зелёные.

## Требования к тестированию

- Fastify inject с настоящими `SaveService` и `SaveStore`. Проверить список после
  успешного действия, завершённую игру после перезапуска, отсутствие файла метаданных
  и загрузку старого сохранения с исходным хешем.
- Проверить запрет `seed` строгой REST-схемой и актуальность сгенерированных схем.
