# GDT-013 — Backend: отказ рукопожатия не теряется, без бесконечного переподключения

## Описание

Найдено в GDT-003 на штатном сервере. На `hello` с неизвестным токеном шлюз
(`apps/server/src/gateway/index.ts`) отправляет `error` `UNAUTHORIZED` и сразу закрывает сокет
(1008). `Backend._process` проверяет `STATE_CLOSED` до чтения пакетов, поэтому `error` не
доставляется, а клиент переподключается по кругу: `CONNECTING → HANDSHAKING → RETRYING`
(замер: четыре цикла за 4 секунды, ни одного сообщения). Так ведёт себя каждый desktop-токен,
который сервер не знает: например, после перезапуска сервера.

Вторая часть: шлюз указывает в `requestId` id отклонённого `hello`, а `GameStore._on_error`
считает любой `error` с `requestId` отказом действия (`action_failed`). Документированный
сигнал для этого случая — `error_received` (godot-client.md §3.1).

## Цель

Экран узнаёт об отказе рукопожатия кодом ошибки и не уходит в бесконечные повторы.

## Scope

- `Backend`: прочитать доступные пакеты до обработки закрытия. Ошибку рукопожатия передать
  как сейчас (`disconnect_session`, затем `message_received`), без повторов.
- `GameStore`: `error` с `requestId`, пришедший при закрытии рукопожатия (переход
  `HANDSHAKING → OFFLINE`), отправлять в `error_received`, а не в `action_failed`.

## Out of Scope

- Изменения шлюза и протокола.
- Экран Pairing уже показывает `error_received` при `OFFLINE` (GDT-003).

## Ожидаемый результат

Неверный токен даёт один `error_received(UNAUTHORIZED)` и состояние `OFFLINE`.

## Критерии приёмки

- [x] Живой GUT-тест: реальный `SessionGateway` без сессии токена отвечает на `hello`, клиент
  получает `error_received("UNAUTHORIZED", …)`, состояние `OFFLINE`, повторов нет.
- [x] Ошибка действия при `ONLINE` по-прежнему приходит как `action_failed`/`action_resolved`.
- [x] Живой тест GDT-003 (`test_pairing_live.gd`, режим production) проверяет текст отказа
  на экране Pairing вместо переподключения.
