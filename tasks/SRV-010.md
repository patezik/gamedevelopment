# SRV-010 — Нативный запуск сервера: npm start без ошибок strip-types

## Описание

`npm start -w @hs/server` выполняет `node src/server.ts`: Node только вырезает типы и не
поддерживает синтаксис TypeScript, требующий преобразования. `SaveDesyncError` в
`packages/core/src/game/save.ts` объявляет поле параметром конструктора (`readonly atAction`), и с
тех пор как `app.ts` подключает сохранения, запуск падает с `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`.
Тесты этого не видят: vitest преобразует TypeScript сам. SRV-001 и SRV-002 исправляли такой же
синтаксис в загружаемых сервером модулях и проверяли загрузку отдельных модулей, но не всего
`server.ts`.

## Цель

Сервер запускается командой `npm start` на поддерживаемой версии Node.

## Scope

- Заменить параметр-свойство в `save.ts` явным полем.
- Тест: дочерний процесс Node без флагов импортирует `app.ts` (весь граф модулей сервера).

## Out of Scope

- Сборка SEA (INT-005).
- Флаг `erasableSyntaxOnly` в tsconfig для всего репозитория.

## Зависимости

- [SAVE-001](SAVE-001.md) — Формат сохранения и replay с проверкой хеша

## Затрагиваемые модули

- `packages/core/src/game/save.ts`
- `apps/server/src/app.test.ts`

## Ожидаемый результат

`npm start -w @hs/server` открывает порт, `GET /api/v1/health` отвечает.

## Критерии приёмки

- [ ] Импорт `app.ts` в Node без флагов проходит (тест).
- [ ] `npm start -w @hs/server` отвечает на `/api/v1/health` (проверено вручную).
- [ ] `npm run tasks:check` и проверки CI зелёные.

## Требования к тестированию

- Тест загрузки модуля в дочернем процессе Node.
