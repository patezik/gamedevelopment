# ENG-008 — portraitRef персонажей: вариант портрета по архетипу

## Описание

`CharacterView.portraitRef` сейчас всегда пустая строка (`packages/core/src/game/views.ts`).
Пайплайн арта ([art-direction.md §6.2, §7.2](../docs/game-design/art-direction.md)) задаёт формат
ссылки `<archetype_id>.<variant>` (`head_doctor.m1`), а варианты внешности различаются полом и
возрастом, которых в данных персонажа нет: пол сейчас следует только из имени в пуле архетипа.

## Цель

Каждый сгенерированный персонаж получает детерминированный `portraitRef`, согласованный с его
именем, и сервер передаёт его в `PlayerView` и контактах `PhoneView`.

## Scope

- Источник варианта: способ указать вариант портрета для имён пула архетипа (например,
  поле `portrait` у записи имени в `archetypes.json` или отдельная таблица) — предложить и
  согласовать в PR; изменение схемы пресета описать в scenario-presets.md.
- Заполнение `portraitRef` в `CharacterView` и `PhoneView.contacts[]` из данных персонажа.
- Пустая строка, если для архетипа нет вариантов.

## Out of Scope

- Показ портретов в клиентах (GDT-012, мобильное приложение).
- Рисование портретов (CNT-012).

## Зависимости

- [CNT-010](CNT-010.md) — Арт-направление и пайплайн ассетов локаций и портретов

## Затрагиваемые модули

- `packages/core/src/game/views.ts`

## Ожидаемый результат

Непустой детерминированный `portraitRef` у персонажей с вариантами портретов.

## Критерии приёмки

- [x] Один seed — одинаковые `portraitRef`; вариант согласован с именем персонажа.
- [x] `portraitRef` не зависит от истины (виновник выбирается после внешности или независимо от неё).
- [x] `npm run lint && npm run typecheck && npm test` зелёные.

## Требования к тестированию

- Unit: детерминизм, формат `<archetype_id>.<variant>`, пустая строка без вариантов; фикстуры
  представлений обновлены.

## Требования к документации

- protocol.md (формат `portraitRef`), scenario-presets.md при изменении схемы архетипов.
