# INT-005 — Упаковка сервера в исполняемый файл (Node SEA) и запуск из Godot

## Описание

В релизе игрок не должен устанавливать Node.js (ADR 0002, риск R-03).

Работа возобновлена 27.11.2026: завершение INT-005 передано от claude-w5 (Timofey10012) агенту egor-claude-int-005 по договорённости в PR #68; переназначение assignee в `main` ждёт подтверждения в PR. Критерий «чистая Windows + привязка телефона» не выполнен: проверка проводится на отдельной машине участника команды по автономной сборке и docs/testing/manual-server-sea.md. Проверка на компьютере разработчика (Node.js установлен, брандмауэр уже разрешён) её не заменяет.

## Цель

Godot-игра запускает встроенный сервер и подключается к нему.

## Scope

- Сборка сервера (бандл + Node.js Single Executable Application) для Windows, Linux, macOS.
- ServerLauncher: запуск дочернего процесса, ожидание /health, завершение при выходе.
- Свободный порт при занятости 7420.
- Подпись/нотаризация — отдельный вопрос (OQ-09).

## Out of Scope

- Экспорт Godot (REL-001).

## Критерии приёмки

- [ ] Godot-сборка на чистой Windows-машине без Node.js проходит привязку телефона.
  На Windows SEA из отдельного рабочего каталога проверены health, каталог сценариев, создание дела seed 2 и POST /pair. Встроенный сервер получает штатные игровые сервисы и каталог content/scenarios рядом с exe. Godot выбирает фактический порт встроенного сервера и ждёт его готовности. На машине разработчика (не чистая Windows) пакет «runtime Godot 4.7.2 + pck + server/» при занятом 7420 поднял сервер на 7421, физический iPhone привязался по Wi-Fi. Проверка готовой Godot-сборки на чистой Windows с физическим телефоном остаётся невыполненной.
- [x] Процесс сервера завершается вместе с игрой. На Linux проверены `OS.kill` при выходе
  и `HS_PARENT_PID` при падении игры. Windows SEA отвечает на health и завершается при
  остановке процесса, указанного в `HS_PARENT_PID`.
- [ ] `npm run tasks:check` и проверки CI зелёные, включая SEA-сборку и smoke на Windows, Linux и macOS
  (прежний зелёный run 45852870465 относится к коду до обновления от `main`; требуется новый run).
