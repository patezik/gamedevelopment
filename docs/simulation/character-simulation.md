# Character Simulation System

Модуль `@hs/core/simulation`. Решение по детализации — [ADR 0013](../architecture/adr/0013-simulation-lod.md).

## 1. Назначение

Все персонажи — автономные участники мира. Они живут по расписаниям, преследуют цели, общаются,
наблюдают, лгут, прячут улики и реагируют на игрока — **в том числе вне его поля зрения**.
Симуляция работает поверх Truth Model: любое действие NPC — событие истины.

## 2. Слои модели персонажа

| Слой | Где | Содержание |
|------|-----|------------|
| Идентичность | `Character` | биография, черты личности, статус, страхи, желания, привычки, доступы |
| Объективная истина | `TruthModel` | что персонаж **на самом деле** делал и где был |
| Знания (Knowledge) | `KnowledgeStore` | что персонаж **знает**: наблюдал, услышал, прочитал, вывел |
| Убеждения (Beliefs) | `Belief.confidence` < 1 или ложная пропозиция | что персонаж **считает** верным (может ошибаться) |
| Память (Memories) | `Belief.fuzzMinutes`, затухание | насколько точно помнит время и детали |
| Ложь (Lies) | `LiePolicy` | что персонаж **намеренно** искажает и почему |
| Состояние агента | `Agent` | текущая активность, цели, настороженность, стресс, LOD |

**Персонажи не читают Truth Model.** Их решения принимаются по `KnowledgeStore` и восприятию.

## 3. Цикл агента

```
на границе блока расписания / завершении шага / триггере:
  обновить стресс и настороженность (wariness) по событиям
  кандидаты = цели из набора, применимые к агенту
  для каждой цели: score = goal.score(agent, worldView)       // личность × знания × стресс × отношения
  если max(score) > порог рутины → activity = goal.plan(...)
  иначе activity = рутина расписания (whereShouldBe)
  запланировать шаги activity в Scheduler (фаза Simulation)
```

### Набор целей (MVP)

| Цель | Когда активна | Что делает | Какие следы оставляет |
|------|---------------|------------|-----------------------|
| `FollowRoutine` | всегда (базовая) | расписание | присутствие (видят другие) |
| `ExecutePlot` | виновник до/во время инцидента | шаги плана из PlotPlanning | по правилам следов |
| `ConcealEvidence` | знает об улике против себя (или своего секрета) и wariness > 0,5 | перемещает/уничтожает след | **всегда вторичный след** (пепел в печи, сломанный замок, свидетель) |
| `AvoidPlayer` | wariness > 0,6, личность с низкой courage | меняет локацию при появлении игрока | изменение расписания (заметно другим) |
| `MeetCharacter` | общий секрет, тревога, роман, сговор | встреча в локации | присутствие, подслушанный разговор |
| `SeekInformation` | исчезновение/смерть знакомого, слухи | расспрашивает других | знания распространяются |
| `SpreadRumor` | extraversion высокая, есть «сочная» пропозиция | рассказывает другим (с искажением) | показания, ссылающиеся на слухи |
| `ProtectSelf` | угроза (Static ≥ 75, вторичный инцидент) | запирается, меняет планы | изменение доступности |
| `ConfrontPlayer` | виновник, wariness > 0,85, ночь, игрок один | нападение (см. survival-horror) | след нападения |

## 4. Восприятие и знания

- Событие с `visibility: public` → все присутствующие получают `Belief(source: observed)`.
- `covert` → наблюдают присутствующие с вероятностью `p = attention(personality, lighting, stress)`.
- Встреча NPC → обмен знаниями: персонаж делится пропозицией, если `trust(a, b) > порог(чувствительность)`
  и пропозиция не в `LiePolicy.conceal`. Переданное знание: `source: told`, `confidence × 0,8`.
- Память: `fuzzMinutes` растёт с прошедшим временем и стрессом; при ответе время округляется
  («около девяти вечера»).
- Вывод (`inferred`): простые правила — «X пропал + X в последний раз видели с Y» → подозрение Y.

## 5. Реакция на игрока

Действия игрока — тоже события истины, наблюдаемые NPC:

- Вопрос по теме T → `wariness += sensitivity(T)` для персонажей, у которых T в `LiePolicy.conceal`.
- Игрок долго не посещает локацию с уликой против виновника → виновник с высокой wariness может
  успеть её спрятать (цель `ConcealEvidence`).
- Обвинение невиновного → реакции (см. [investigation-model.md](../investigation/investigation-model.md) §6).
- Исчезновение/смерть персонажа → `SeekInformation`, изменение планов, рост стресса.

## 6. Детерминизм и производительность

- RNG: подпоток `sim/agent/<characterId>`; порядок обработки — по ключу Scheduler.
- LOD `focus` / `background` (ADR 0013); переключение по локации игрока и сюжетной активности.
- Бюджеты: 60 игровых минут × 8 персонажей ≤ 10 мс; 24 ч предыстории ≤ 200 мс (QA-002).

## 7. Тесты (SIM-*)

- Персонаж следует расписанию без игрока (24 ч), инварианты истины соблюдены.
- Наблюдения: присутствующий знает о public-событии, отсутствующий — нет.
- Обмен знаниями при встрече соблюдает trust и conceal.
- `ConcealEvidence` создаёт вторичный след (property-тест по 500 seed).
- Реакция на вопросы игрока повышает wariness только у затронутых.
- Одинаковые seed + действия → одинаковый журнал (golden-хеш).
- Бенчмарк в пределах бюджета.
