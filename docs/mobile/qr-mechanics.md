# QR-механики

## 1. Три разных QR — не путать

| QR | Где показывается | Чем сканируется | Формат | Назначение |
|----|------------------|-----------------|--------|------------|
| **QR Expo Go** | терминал / браузер разработчика (`npx expo start`) | приложение Expo Go / системная камера | `exp://…` | **Только разработка**: открыть JS-бандл в Expo Go. Не имеет отношения к игре и не существует в релизе. |
| **QR привязки** | экран привязки Godot | камера **внутри** companion-приложения (экран `/pair`) | `hs1:pair:<host>:<port>:<code>` | Подключить телефон к игровой сессии |
| **QR улики** | оверлей фиксации улики в Godot | приложение Camera виртуальной ОС | `hs1:ev:<sessionTag>:<tokenId>:<sig>` | Зафиксировать улику — игровая механика |

Приложение отклоняет `exp://` и любые неизвестные форматы с понятным сообщением.

## 2. Жизненный цикл QR улики

```
[ядро] игрок изучил точку с clue.captureMode = "qr"
   → EvidenceTokenPort.issue(clueId, expiresAt = now + 120)      (сервер: запись токена)
   → PlayerView.pendingCapture { tokenId, clueTitle, expiresInMinutes }
[Godot] GET evidence-qr/:tokenId → рисует QR в оверлее «Сфотографируйте улику»
[phone] Camera: распознан hs1:ev:… → qr.scan { raw }
[сервер] проверки (по порядку):
   1. формат                      → QR_INVALID
   2. sessionTag == текущая сессия → QR_WRONG_SESSION
   3. HMAC подпись                 → QR_INVALID
   4. токен существует             → QR_INVALID
   5. срок (игровое время)         → QR_EXPIRED
   6. не использован               → QR_ALREADY_USED (идемпотентный ответ с clueRef)
   7. игровые предусловия (игрок всё ещё в локации, жив, не в блокирующем взаимодействии) → QR_PRECONDITION_FAILED
   → engine.dispatch({ type: "captureEvidence", tokenId })  (2 игровые минуты)
   → токен помечен usedAt
[оба клиента] view.update: улика в gallery, pendingCapture снят; event: «Улика сохранена»
```

Токен **не содержит** содержимого улики и не позволяет вывести решение. Срок истёк — игрок
может снова изучить точку (новый токен, снова тратится время).

## 3. Ошибки камеры (мобильное приложение)

| Ситуация | Поведение |
|----------|-----------|
| Разрешение не выдано | экран объяснения + кнопка запроса; при «больше не спрашивать» — ссылка в настройки ОС |
| Камера недоступна (симулятор, занята) | сообщение и ручной ввод кода (только для QR привязки; для улик — не допускается) |
| Неизвестный формат / `exp://` | «Это не игровой код» |
| Повторное распознавание одного кода | дебаунс 2 с на одинаковое содержимое |
| Нет соединения | код не отправляется; «Нет связи с игрой» |
| Ответ с ошибкой | человекочитаемое сообщение по `ErrorCode` (таблица в `src/os-apps/camera/errors.ts`) |

## 4. Почему улика не вводится вручную

Ручной ввод кода улики не поддерживается: механика задумана как «сфотографировать» улику
телефоном героя. Для доступности (нет камеры) — открытый вопрос OQ-07.
