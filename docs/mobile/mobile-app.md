# Mobile Companion App (`apps/mobile`)

Стек — [ADR 0007](../architecture/adr/0007-mobile-stack.md). QR — [qr-mechanics.md](qr-mechanics.md).

## 1. Принципы

- Нативное приложение React Native (Expo), **не PWA и не веб-страница**.
- Приложение — «телефон героя»: виртуальная ОС с собственными приложениями. Все данные — игровые,
  приходят с сервера в `PhoneView`.
- **Никакого доступа к реальным личным данным** (контакты, SMS, фото, звонки, геолокация).
  Приложение само запрашивает только камеру и только для сканирования игровых QR; на iOS система
  дополнительно показывает запрос доступа к локальной сети при первом подключении к игре.
  Политика и сверка с кодом — [privacy-policy.md](../legal/privacy-policy.md).
- Сервер — авторитет; приложение не хранит игровое состояние, кроме кэша последнего
  `PhoneView` для мгновенного отображения при переподключении.

## 2. Структура

```
apps/mobile/
├── app/                         — Expo Router
│   ├── _layout.tsx              — провайдеры, подключение, статус сети
│   ├── index.tsx                — версия протокола и вход в демонстрационную оболочку
│   ├── pair.tsx                 — экран привязки (скан QR привязки / ручной ввод)
│   └── os/
│       ├── _layout.tsx          — общий центр уведомлений и оверлей звонка
│       ├── index.tsx            — домашний экран ОС (сетка приложений)
│       └── [appId].tsx          — открывает приложение из реестра
├── src/
│   ├── os/                      — оболочка: StatusBar, HomeGrid, AppFrame, NotificationCenter, IncomingCallOverlay, effects/
│   ├── os-apps/                 — по каталогу на приложение
│   │   ├── registry.ts          — список манифестов (единственное место регистрации)
│   │   ├── camera/  contacts/  messages/  gallery/  notes/  maps/  browser/  files/  calls/  settings/
│   ├── connection/              — WsClient, backoff, протокольные обработчики
│   ├── stores/                  — Zustand: connectionStore, phoneStore (PhoneView), uiStore
│   ├── pairing/                 — разбор QR привязки, POST /pair, SecureStore
│   └── lib/                     — общие утилиты
└── app.json                     — разрешения: камера (iOS NSCameraUsageDescription, Android CAMERA),
                                   iOS NSLocalNetworkUsageDescription; микрофон, хранилище и
                                   SYSTEM_ALERT_WINDOW отключены (плагин expo-camera, blockedPermissions)
```

## 3. Реестр приложений виртуальной ОС

```ts
interface OsAppManifest {
  id: string;                         // "messages"
  title: string;                      // "Сообщения"
  icon: IconRef;                      // { glyph: string } — текстовый символ, без картинок и иконочных шрифтов
  component: React.ComponentType<OsAppProps>;
  badge?: (view: PhoneView) => number;
  enabled?: (view: PhoneView) => boolean;   // например, браузер без сигнала при Static ≥ 90
  order: number;
}
```

Чтобы добавить приложение: создать каталог `src/os-apps/<id>/` с `manifest.ts` и компонентом,
добавить одну строку в `registry.ts`. Бейдж и доступность по умолчанию берутся из `PhoneView.apps`
(`badge`, `enabled`); `badge`/`enabled` манифеста переопределяют бейдж и могут только дополнительно
отключить приложение. До подключения сервера оболочка работает на фикстуре `phone-view.mid.json`
(`src/os/demoPhoneView.ts`), а до реальных приложений каждое — заглушка «В разработке». Приложения не импортируют друг друга; общаются через
`phoneStore` и действия (`sendAction`). Тест реестра проверяет уникальность `id` и наличие компонентов.

## 4. Приложения (MVP)

| Приложение | Данные (`PhoneView`) | Действия |
|------------|----------------------|----------|
| Camera | — | сканирование QR → `qr.scan` |
| Contacts | `contacts` | карточка контакта → `call` и переход в Calls / переход в Messages; звонок недоступен при активном звонке |
| Calls | `callLog`, `activeCall` | `call`, `answerCall`, `callChoice` (реплики NPC и варианты игрока; завершение звонка сервером). Журнал: пропущенные выделены, номер вне контактов показан как «Неизвестный номер» |
| Messages | `threads` | `message` (шаблонные ответы из `availableReplies`) |
| Gallery | `gallery` (снимки улик, сюжетные фото) | просмотр, увеличение, метаданные |
| Files | `files` (документы, скрытые/зашифрованные) | `openFile`, `unlockFile(password)` |
| Notes | `notes` (авто-журнал + заметки игрока) | `addNote` |
| Maps | `mapPins` (локации, наблюдения) | — |
| Browser | `browserPages` (внутриигровые страницы) | `browse(pageId)` |
| Settings | локальные настройки | язык (ru/en, QA-003: словари `src/i18n`, `t(key)`), размер текста, вибрация, снижение эффектов, отвязать устройство (сначала best-effort `DELETE /sessions/:id/device` с токеном устройства и таймаутом 3 с, сбой сети не мешает, затем стирание токена и закрытие соединения; [ADR 0024](../architecture/adr/0024-phone-initiated-unpair.md)), о приватности; значения сохраняются между запусками в expo-secure-store (ключ `hs.settings`), без отдельной зависимости |

Notes и Maps показывают только `PhoneView.notes` и `PhoneView.mapPins`. Notes сортирует записи от новых
к старым, различает «Журнал» и «Заметка», отправляет `addNote` с обрезанным текстом (до 500 знаков)
и не отправляет без связи; новая запись появляется после `view.update`. Maps группирует метки по
`locationId` без показа технических id (названий мест в виде нет, поэтому «Место N»); время
наблюдения — часы дела `H:MM` от начала сценария (`src/os/caseTime.ts`). Действия уходят через
`sendAction` (`gameConnection`).

## 5. Состояние и подключение

- `connectionStore`: `status: "unpaired" | "connecting" | "online" | "reconnecting" | "offline"`,
  `lastSeq`, `stateVersion`, ошибки.
- `phoneStore`: последний `PhoneView`; обновляется только из `view.update` (с проверкой
  `stateVersion` по возрастанию).
- Все входящие сообщения валидируются zod-схемами `@hs/protocol`; невалидные — лог + игнор.
- Переподключение: экспоненциальная задержка ([protocol.md §7](../backend/protocol.md)); при
  `DEVICE_REVOKED` — удаление токена и возврат на `/pair`.
- Приложение в фоне: соединение закрывается ОС; при возврате — `hello` с `resume`.

Реализация (`src/connection`, `src/stores`):

- `WsClient`: `hello{phone}` сразу после открытия сокета; `resume` (`lastSeq`, `stateVersion`)
  шлётся, если уже принят снимок. После `welcome` — `ping` с `ack` каждые 10 с. 30 с тишины —
  обрыв. Задержка переподключения 0,5 → 1 → 2 → 4 → 8 с (±20 % джиттер), сбрасывается после
  `welcome`.
- Статусы: первое подключение — `connecting`; обрыв — `reconnecting`; после 3 неудачных попыток —
  `offline` (попытки продолжаются); фон — `offline` без попыток, возврат в `active` — немедленный
  `hello` с `resume`. В `reconnecting` и `offline` показывается баннер «Нет связи с игрой».
- `phoneStore` принимает только `PhoneView` и только `stateVersion` строго больше текущего.
  `resync` и `welcome` со старшей версией у клиента (перезапуск сервера) сбрасывают версию, снимок
  принимается любой.
- `DEVICE_REVOKED`: сокет закрыт, токен удалён из SecureStore, кеш вида очищен, переход на `/pair`.
  `PROTOCOL_MISMATCH`, `SESSION_CLOSED`, `SESSION_NOT_FOUND` останавливают попытки; код остаётся в
  `connectionStore.lastError`.
- Лог невалидного сообщения не содержит ни тела, ни токена.

## 6. Иммерсивность

- Входящие сообщения и звонки инициирует сервер (`event`): оверлей звонка, вибрация, звук.
  `NotificationCenter` (`src/os`) строится по `PhoneView.notifications` и `activeCall`: тост нового
  уведомления, колокол с бейджем, список, оверлей звонка; вибрация (`expo-haptics`) и звук
  (`expo-audio`) выключаются настройками `settingsStore`. Уведомления на первом рендере — история
  без тоста. Центр смонтирован один раз в `app/os/_layout.tsx`: уведомления и звонки видны
  поверх любого приложения ОС, переходы между приложениями не повторяют вибрацию и звук.
- Неизвестные контакты, изменения контактов, новые фото, скрытые файлы — данные `PhoneView`.
- `src/os/effects` использует серверный `effects.glitchLevel` от 0 до 100. При 0 интерфейс
  стабилен. Выше 0 растут дрожание (Reanimated), интенсивность полос экранного шума и сдвиг
  фрагментов превью в галерее. С уровня 50 заголовок открытого приложения раз в 5 секунд
  на 180 мс показывает «ШУМ». VoiceOver всегда получает исходный заголовок. Названия фото
  и данные расследования сохраняются без подмены.
- Настройка «Снизить эффекты» и системное «Уменьшение движения» отключают все эти искажения.
  Экран камеры всегда стабилен. Обои домашнего экрана определяет
  `effects.wallpaperVariant`: для вариантов санатория используются тонированные версии
  пластин тропы к озеру. Для отсутствующего или неизвестного варианта используется однотонный
  фон. Смена статичных обоев работает и при сниженных эффектах.
- В сетке [Gallery](../../tasks/MOB-008.md) `PhotoPreview` искажает графику миниатюры
  `EvidenceCard`. Подпись и доступное имя кнопки сохраняются. Полноэкранный снимок, метаданные
  и масштабирование доступны без искажения миниатюры.

### Контент телефона в пресете

Контент лежит в `content/scenarios/<id>/phone/*.json` в формате `phoneTemplatesSchema`
([scenario-presets.md §7](../procedural-generation/scenario-presets.md)). Записи без `event`
попадают в стартовый телефон героя (`initialPhoneState`): страницы, файлы и единственные стартовые
обои. Записи с `event` сервер выдаёт при наступлении события; записи с одинаковыми `event` и видом —
варианты, из которых выбирает `Rng`. Выдачу по событиям реализует движок; контент только называет
события.

В `sanatorium_winter` (CNT-006): `browser.json` (сайт санатория, распорядок, история, новости,
погода, форум), `files.json` (путёвка, памятки, оповещение МЧС, файлы планшета медсестры),
`messages.json` (сообщения NPC), `wallpapers.json` (обои и их искажения). Полноту событий,
подстановки и согласованность с данными сценария проверяет `sanatorium-phone.test.ts`.

| Событие | Что выдаёт | Подстановки |
|---------|------------|-------------|
| `npc_tip_presence`, `npc_tip_item`, `npc_tip_place` | наводка NPC: кто где был, у кого вещь, куда заглянуть | `{who}`, `{who_f}`, `{where}`, `{time}`, `{item}`, `{me_f}` |
| `npc_rumor_presence`, `npc_rumor_relation`, `npc_rumor_vague` | слух: с чужих слов, об отношениях, без фактов | `{who}`, `{who_f}`, `{where}`, `{time}`, `{a}`, `{b}`, `{relation}`, `{me_f}` |
| `npc_threat` | анонимная угроза ([survival-horror.md §4](../game-design/survival-horror.md)) | — |
| `npc_request_meet`, `npc_request_item`, `npc_request_discretion` | просьба о встрече, о вещи, о молчании | `{where}`, `{time}`, `{item}`, `{me_f}` |
| `contact_shared`, `interrogated_calm`, `interrogated_nervous`, `interrogated_hostile` | реакция: NPC дал номер; NPC пишет после допроса, тон выбирает вызывающий код | `{me_f}` |
| `incident_discovered`, `secondary_incident` | известие о теле или о вторичном инциденте | `{who}`, `{who_f}`, `{where}`, `{me_f}` |
| `blackout` | сообщения, новость, тёмные обои; `id` из `preset.criticalEvents` | `{me_f}` |
| `night` | ночные сообщения (период `night`) | `{me_f}` |
| `static_25`, `static_50`, `static_75` | пороги Static ([survival-horror.md §3](../game-design/survival-horror.md)): обои, сообщения с неизвестных номеров, файлы и страницы-сбои | — |
| `sanity_low`, `rest` | искажённые обои при рассудке не выше `phoneInterferenceSanity`; исходные обои после отдыха | — |

Подстановки — как в текстовых шаблонах CNT-005: `{who}` — имя в именительном падеже, `{where}` и
`{item}` — названия (в тексте они стоят в кавычках «»), `{who_f}` и `{me_f}` — окончание «а» для
женского рода субъекта и отправителя. Тексты наводок и слухов одинаковы для правды и лжи:
подстановки берутся из убеждений отправителя, а не из истины. Сообщения не называют архетипов и
имён из пулов, поэтому отправителем, жертвой или виновником может оказаться любой персонаж.
Страницы, файлы и обои подстановок не содержат.

Шаблон обоев — идентификатор варианта (`pine_forest`, `pine_forest_noise`, `pine_forest_static`,
`pine_forest_silhouette`, `pine_forest_inverted`, `pine_forest_dark`), `title` — описание для
художника (CNT-010). Файлы планшета медсестры есть в телефоне с начала, но скрыты и заперты:
движок раскрывает их событием `FileRevealed`, когда герой находит планшет `it_nurse_tablet` (схема
шаблона не выражает это условие), а пароль герой узнаёт со стикера `it_password_note` в дежурной
комнате процедурного корпуса. Галлюцинаций контент не содержит, их генерирует SURV-005.

## 8. Запуск в Expo Go

Из корня репозитория:

```bash
npm ci
npm run start -w @hs/mobile
npm run typecheck -w @hs/mobile
npm test -w @hs/mobile
```

Установите Expo Go с поддержкой SDK 58 и отсканируйте QR разработки из терминала. Телефон и
компьютер должны быть в одной сети. В Expo Go и Expo CLI войдите в один аккаунт. На стартовом
экране нажмите «Открыть телефон». Оболочка использует демоданные, сервер игры ей не требуется.
Откройте «Заметки» и нажмите «Домой» для проверки возврата. «Браузер» отключён в демоданных.

### Ручная проверка эффектов на iPhone (MOB-011)

В двух терминалах из корня worktree после `npm ci`:

```bash
node tools/mobile/preview-phone-effects.mjs
npm run start -w @hs/mobile -- --lan --port 8082
```

1. Откройте [панель MOB-011](http://127.0.0.1:7421/) на компьютере. Отсканируйте на iPhone QR-код
   **Expo Go** из терминала Metro. В приложении выберите «Привязать телефон» → ручной ввод. Введите LAN-адрес
   компьютера с портом `7421` и код с панели. Если в Expo Go открыта другая тестовая привязка, после
   прогона верните её через экран привязки.
2. На панели можно отправить любое целое значение 0–100. Начните с 0, 25, 49, 50, 75 и 100, затем
   вернитесь к 0. Сравните домашний экран и «Галерею». При 0 дрожание, шум и сдвиг превью отсутствуют.
   На уровнях от 50 задержитесь в «Галерее» на 5 секунд, чтобы увидеть короткую подмену заголовка.
   При 0 отдельно проверьте смену обоев через выпадающий список.
3. На 100 включите в виртуальной ОС «Настройки» → «Снизить эффекты». Проверьте, что дрожание, шум,
   подмена заголовка и искажение превью пропадают. Выключите переключатель и повторите с системной
   настройкой iOS «Универсальный доступ» → «Движение» → «Уменьшение движения». Откройте Expo Go
   с уже включённым уменьшением движения, затем выключите его и проверьте возврат дрожания
   без перезагрузки приложения.
4. При 100 и обоих выключенных переключателях откройте «Камеру». Изображение и интерфейс должны
   оставаться стабильными, даже если открыть камеру в момент дрожания. Наведите камеру на
   **тестовый QR с панели**, дождитесь «Улика сохранена
   в галерею». Панель и сканирование используют только тестовый снимок. Вернитесь на домашний
   экран и убедитесь, что эффекты возобновились. Завершите оба процесса через Ctrl+C.

При повторной проверке после интеграции с MOB-008 на уровне 100 откройте «Галерею».
Проверьте искажение графики миниатюры и читаемость подписи. С VoiceOver кнопка снимка должна
объявляться один раз со своим названием. Откройте снимок, проверьте время, место, изменение
масштаба и возврат к сетке. Повторите проверку миниатюр с каждым переключателем сокращения
эффектов отдельно, затем выключите оба и повторите шаг со сканированием при 100.

Стенд отправляет обычные `view.update` с синтетическим `PhoneView`, принимает тестовый QR и
не требует запуска игры. Панель доступна с компьютера по loopback. Стенд использует порты
`7421` и `8082`, отдельно от окружения GDT-003/INT-001.
