# 0023. Seed в публичном списке сохранений

- **Статус:** Accepted. [Владелец подтвердил решение](https://github.com/patezik/gamedevelopment/issues/189#issuecomment-7198636361).
- **Дата:** 2026-11-26
- **Связанные задачи:** SRV-007, SRV-015, SRV-016, PROTO-006
- **Заменяет / заменён:** —

## Контекст

Публичный список сохранений использовался при явном подключении модуля и возвращал seed
незавершённых дел. По идентификатору сценария и seed можно повторить генерацию. Для завершённых
прохождений seed уже доступен в итоговом представлении. Штатное подключение списка запланировано
в SRV-015. [ADR 0021](0021-ending-recap.md)

## Рассмотренные варианты

1. Выдавать seed завершённых дел. Для старых сохранений подтверждение исхода потребовало бы
   воспроизведения журнала с проверкой хеша.
2. Убрать seed изо всех записей. Активные и завершённые дела используют одну схему метаданных.

## Решение

Для `GET /api/v1/saves` выбран второй вариант. Публичный `SaveSummary` содержит `saveId`,
`scenarioId`, `updatedAt` и `gameTime`. Сервер строит список по метаданным и проверяет его
строгой схемой `SaveList`. Seed хранится в `SaveFile` для загрузки и replay и доступен игроку
после завершения дела в `EndingView.seed`.

## Последствия

- Новая REST-схема вступает в силу до штатной регистрации маршрута. Потребители прежней схемы
  в тестах обновляются вместе с сервером. Версию WebSocket-протокола и совместимость
  сохранений определяют действующие контракты.
- Список строится без восстановления сохранений и определения исхода. Старые файлы
  используют прежний путь загрузки с проверкой исходного контрольного хеша.
