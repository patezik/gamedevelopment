# 0009. Протокол: zod — источник схем, экспорт JSON Schema для Godot, полные снимки представлений

- **Статус:** Accepted
- **Дата:** 2026-10-30
- **Связанные задачи:** FND-004, PROTO-001…PROTO-003

## Контекст

Три клиента протокола: сервер (TS), мобильное приложение (TS), Godot (GDScript). Нужна
единая спецификация, проверка схем данных и контрактные тесты.

## Решение

1. **Источник истины — zod 4 схемы** в `@hs/protocol`. Из них выводятся TS-типы (`z.infer`) и
   экспортируются JSON Schema (`z.toJSONSchema`) в `packages/protocol/schemas/*.json`
   (генерируемые файлы коммитятся; CI проверяет, что они актуальны).
2. **Godot** получает: (а) сгенерированный `protocol_constants.gd` с типами сообщений и кодами
   ошибок; (б) JSON-фикстуры `packages/protocol/fixtures/*.json`, на которых GUT-тесты проверяют
   разбор. Полная валидация JSON Schema в Godot не выполняется: сервер — авторитет и валидирует
   всё входящее.
3. **Конверт сообщения:** `{ v: 1, type, id, seq?, ack?, payload }`. `seq` — монотонный номер
   серверных событий в сессии для возобновления.
4. **Представления передаются полными снимками** (`view.update` с `stateVersion`). Размер
   `PlayerView` и `PhoneView` в MVP — единицы килобайт; дифференциальные патчи — оптимизация
   после MVP, если измерения покажут необходимость.
5. **Версионирование:** `PROTOCOL_VERSION` (целое). Несовместимое изменение увеличивает его;
   сервер отвечает `PROTOCOL_MISMATCH` клиентам другой версии.

## Последствия

- Изменение протокола = изменение схемы + регенерация + обновление фикстур в одном PR.
- Godot-разработчикам нужен Node.js для регенерации констант (`npm run protocol:gen`).
