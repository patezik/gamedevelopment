# 0019. Совместимость сохранений по версии генератора

- **Статус:** Proposed
- **Дата:** 2026-11-24
- **Связанные задачи:** QA-004, SAVE-001, SRV-007
- **Заменяет / заменён:** —

## Контекст

Один seed может дать разные расследования после изменения генератора. Согласно
[ADR 0004](0004-determinism.md), изменения, влияющие на результат генерации, требуют новой
версии. [ADR 0014](0014-save-system.md) сохраняет версию вместе с журналом и допускает отказ
в загрузке. Чекпойнт содержит состояние на границе действия, но для продолжения игры всё ещё
нужны совместимые правила генерации и replay.

## Рассмотренные варианты

1. Поставлять генераторы и контент прошлых версий. Игрок сможет продолжить старое прохождение,
   но каждую комбинацию генератора, контента и правил replay придётся сопровождать.
2. Мигрировать сохранение при обновлении. Для каждой пары версий потребуется определить, как
   перенести расследование, действия и состояние чекпойнта, и проверить эквивалентность результата.
3. Принимать только точное совпадение версии. Для MVP достаточно текущего генератора и
   существующего механизма проверки журнала.

## Решение

Для MVP выбран вариант 3. После проверки структуры файла и цепочки журнала `loadSave`
сравнивает строку `SaveFile.generatorVersion` с фактической версией в `ReplayRuntime`.
`gameReplayRuntime` берёт её из сгенерированного расследования. Сравнение точное, включая
patch и суффиксы. При совпадении загрузчик проверяет начальный хеш, чекпойнт, состояния после
действий и финальный хеш по ADR 0014.

При расхождении загрузка завершается до восстановления чекпойнта и воспроизведения действий.
Для корректного журнала REST возвращает HTTP 422 с `SAVE_DESYNC`, `atAction: 0` и сообщением,
в котором указаны версия файла и версия генератора сервера. Новая сессия не создаётся,
исходный файл остаётся доступным для загрузки совместимой сборкой.

## Последствия

- Обновление генератора может потребовать от игрока завершить прохождение в прежней сборке.
  Точное совпадение версий допускает проверку replay, но само по себе не гарантирует успеха.
- Будущая миграция требует отдельного ADR с перечислением поддерживаемых пар версий и
  критерием эквивалентности игрового состояния. Для каждой пары нужны сохранение исходной
  сборки, проверка исходного журнала и тесты полного replay и восстановления с чекпойнта.
  Миграция должна записывать отдельную копию и проверять её загрузку целевой сборкой,
  сохраняя оригинал при ошибке.
