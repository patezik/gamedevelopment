# 0001. Монорепозиторий: npm workspaces + Godot-проект

- **Статус:** Accepted
- **Дата:** 2026-10-30
- **Связанные задачи:** FND-001, FND-009

## Контекст

Проект состоит из трёх приложений (Godot desktop, Expo mobile, Node server) и общих TypeScript-пакетов
(Game Core, генератор, валидатор, протокол). Над ним параллельно работают AI-агенты, которым нужен
единый источник истины: код, документация, задачи и ADR в одном месте. Протокол должен меняться атомарно
во всех клиентах.

## Рассмотренные варианты

1. **Отдельные репозитории** на каждое приложение — независимые релизы, но изменения протокола требуют
   синхронизации нескольких PR; агенту сложнее увидеть всю систему.
2. **Монорепозиторий с pnpm** — строгая изоляция зависимостей, но с Expo/Metro исторически требовал
   дополнительной настройки (`node-linker=hoisted`), что повышает порог входа.
3. **Монорепозиторий с npm workspaces** — встроено в Node.js, поддерживается Expo для монорепозиториев
   «из коробки», не требует дополнительных инструментов.

## Решение

Вариант 3. Структура:

```
apps/desktop   — Godot 4.7 проект (не является npm-пакетом)
apps/mobile    — Expo-приложение (@hs/mobile)
apps/server    — Session Server (@hs/server)
packages/core       — @hs/core: headless игровое ядро
packages/generator  — @hs/generator: процедурная генерация расследований
packages/validator  — @hs/validator: проверка расследований, seed sweep
packages/protocol   — @hs/protocol: схемы сообщений и представлений
content/            — данные сценариев (JSON)
tools/              — служебные скрипты (задачи, ссылки, тестовые клиенты)
```

Пакетный префикс — `@hs/` (Hollow Signal). Godot-проект живёт в том же репозитории и получает
контрактные фикстуры из `packages/protocol/fixtures`.

## Последствия

- Изменения протокола делаются одним PR во всех клиентах.
- CI должен запускать только затронутые части (фильтр путей в workflow).
- Mobile-приложение не должно импортировать `@hs/core`, `@hs/generator`, `@hs/validator`: истина
  расследования никогда не попадает на устройство (проверяется ESLint-правилом `no-restricted-imports`).
