# 0012. Задачи — Markdown-файлы с frontmatter в репозитории

- **Статус:** Accepted
- **Дата:** 2026-10-30
- **Связанные задачи:** все

## Контекст

Репозиторий должен быть единственным источником истины. AI-агенты должны находить задачи,
проверять зависимости и назначать себя без внешних систем и прав администратора.

## Рассмотренные варианты

1. **GitHub Issues/Projects** — удобный UI, но требует API-доступа, не версионируется вместе с
   кодом, агенту без `gh` недоступно.
2. **Файлы задач в репозитории** — доступны любому агенту с git; машиночитаемы; проверяются CI.

## Решение

Вариант 2. Каждая задача — `tasks/<ID>.md` (имя файла не зависит от названия, чтобы переименование
задачи не ломало ссылки) с YAML-frontmatter (машиночитаемые поля) и
обязательными разделами. Инструмент `tools/tasks/tasks.mjs` (без зависимостей):

- `validate` — схема, уникальность ID, существование зависимостей, отсутствие циклов,
  согласованность статусов, вехи из roadmap;
- `ready` — задачи, готовые к взятию (все зависимости `done`);
- `index` — генерация `tasks/INDEX.md`.

**Захват задачи** — атомарный push коммита в `main`, меняющего только frontmatter задачи
(`status: in_progress`, `assignee`, `claimed_at`). Git отклонит push при гонке — агент делает
`git pull --rebase` и перепроверяет статус. Процесс — в [AGENTS.md](../../../AGENTS.md).

## Последствия

- GitHub Issues можно использовать для обсуждений, но статус задачи живёт в файле.
- Если `main` защищён от прямых push, захват выполняется мини-PR с меткой `claim`
  (описано в AGENTS.md как запасной вариант).
