# 0021. Хронология и seed в итоговом PlayerView

- **Статус:** Accepted — подтверждено владельцем 26.11.2026
- **Дата:** 2026-11-26
- **Связанные задачи:** ENG-006, ENG-012, GDT-009
- **Заменяет / заменён:** —

## Контекст

После завершения расследования экран Ending показывает разбор дела и данные для его повтора.
[ADR 0002](0002-headless-game-core.md) оставляет журнал истины на сервере. ENG-006 уже разрешает
показ ограниченной проекции через `PlayerView.ending.recap` после конца игры.

## Рассмотренные варианты

1. Расширить итоговый `PlayerView`. Используется существующее условие завершения игры.
   Итоговый снимок восстанавливает данные при переподключении.
2. Запрашивать разбор отдельным сообщением. Для него нужны обработчик, отдельная проверка
   состояния сессии и повторный запрос при переподключении.

## Решение

Выбран первый вариант. Ядро включает `seed` и `scenarioId` в `PlayerView.ending` только после
того, как `endingOf` определит концовку. Seed передаётся дословно. Вместе с идентификатором
сценария он позволяет повторить генерацию с той же версией генератора и тем же контентом.

В `ending.recap.timeline` входят события из `IncidentRecord.keyEventIds` в порядке времени и
добавления в журнал. Запись содержит игровую минуту со знаком, название места, имена
участников и короткое нейтральное описание. Участники включают действующих лиц и персонажей,
на которых направлено действие. Для незнакомого действия используется общий текст.

## Последствия

- Текущая проекция всегда заполняет новые поля. Схема v1 допускает их отсутствие у прежних
  серверов. Старый Godot читает знакомые поля итогового снимка. Инструменты со строгой
  TypeScript-схемой обновляются вместе с сервером, как в [ADR 0020](0020-player-known-map.md).
  Старая строгая схема отклоняет новый итоговый снимок.
- `PhoneView` сохраняет прежнюю форму. До завершения игры представления не раскрывают seed
  и разбор. Отладочные маршруты сохраняют действующие ограничения.
- При явном подключении модуля сохранений `GET /api/v1/saves` возвращает seed, в том числе для
  незавершённых игр. Штатный запуск не регистрирует этот маршрут. За публичный ответ списка
  отвечает [SRV-016](../../../tasks/SRV-016.md) до подключения маршрута в SRV-015.
  Последующее решение по [OQ-40](../../planning/open-questions.md#решённые) зафиксировано
  в [ADR 0023](0023-save-list-seed.md).
- Godot форматирует хронологию и использует для статистики `clock`, `caseBoard` и `vitals` из
  итогового снимка. Формат сохранения и контрольный хеш не меняются.
