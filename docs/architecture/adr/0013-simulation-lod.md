# 0013. Событийная симуляция персонажей с уровнями детализации

- **Статус:** Accepted
- **Дата:** 2026-10-30
- **Связанные задачи:** SIM-001…SIM-007, TIME-002, TIME-003

## Контекст

Персонажи действуют автономно и вне видимости игрока. Симулировать каждую минуту каждого
персонажа в многодневном сценарии дорого и не нужно. Симуляция должна быть детерминированной.

## Решение

1. **Событийная модель.** Нет глобального тика по минутам. Персонаж планирует `Activity`
   (последовательность шагов с длительностями); завершение шага — событие в общей очереди
   `Scheduler`. Время продвигается действиями игрока (TimeSystem), очередь обрабатывается до
   нового момента времени.
2. **Уровни детализации (LOD):**
   - `focus` — персонажи в локации игрока и соседних, а также «сюжетно активные»
     (виновник во время сокрытия, персонажи с активной целью). Шаги до 5 минут, наблюдения
     вычисляются по каждому событию.
   - `background` — остальные. Обрабатываются на границах блоков расписания и по триггерам;
     встречи вычисляются пересечением интервалов присутствия в локациях.
   Переход между уровнями не меняет уже записанную истину; он влияет только на детализацию будущих
   событий. Поскольку уровень зависит от действий игрока, результат детерминирован при той же
   последовательности действий.
3. **Принятие решений.** Утилитарный выбор намерения (utility AI) из набора целей; веса зависят от
   личности, знаний, стресса, отношений. Равенство разрешается подпотоком RNG персонажа.
4. **Бюджет:** продвижение времени на 60 игровых минут при 8 персонажах — не более 10 мс в Node.js
   (QA-002); 3 игровых дня предыстории — не более 200 мс.

## Фактические цифры (SIM-007)

`node packages/core/test/performance/simulation.ts`: лучшее из 15 запусков после прогрева, 8 NPC с
рутинами по кольцу из 8 локаций, измеряется только `TimeSystem.advance` (Node.js, машина
разработчика, 2026-11-24). Измерялся `SimulationRunner`: рутины, перемещения, события истины и
наблюдения. Цели из SIM-004…SIM-006 в замер не входят.

| Сценарий | Время | Бюджет |
|----------|-------|--------|
| 60 минут, `background` | 0,28 мс | 10 мс |
| 60 минут, `focus` в локации 0 | 0,45 мс | 10 мс |
| 24 часа предыстории | 1,21 мс | 200 мс |
| 3 дня предыстории | 3,83 мс | 200 мс |

`vitest bench` в Vitest 5 недоступен (экспорта `bench` нет), поэтому бенчмарк — отдельный скрипт по
образцу `scheduler.ts`. Пороги в CI — QA-002 (ниже).

## Бюджеты в CI (QA-002)

`npm run bench` запускает скрипты `packages/core/test/performance/*.ts`,
`packages/generator/test/performance/history-sim.ts` и `packages/generator/bench/generation.ts`
(генерация расследования целиком, бюджет 500 мс из ADR 0006) отдельным джобом CI `Performance budgets`
(без покрытия, параллельно основному джобу). Строка проходит, если время меньше абсолютного бюджета
**и** не хуже базовой линии более чем на 20 %. Базовая линия `packages/core/bench/baseline.json`
хранит время относительно калибровочной нагрузки на той же машине (абсолютные миллисекунды на разных
машинах не сравнимы). Обновление базовой линии — осознанное: `BENCH_UPDATE=1 npm run bench`, файл
коммитится вместе с причиной в PR.

Базовая линия для `background` (0,000567) снята на Ubuntu-раннере GitHub Actions в
[прогоне QA-002](https://github.com/patezik/gamedevelopment/actions/runs/45669432892).
CI отдельно вводит задержку 210 мс в замер планировщика и проверяет, что бенчмарк
завершается ошибкой именно из-за превышения бюджета.

## Последствия

- Нет «мгновенной телепортации»: перемещение всегда занимает время по графу локаций.
- Отладка через журнал истины: любое действие NPC оставляет `TruthEvent`.
