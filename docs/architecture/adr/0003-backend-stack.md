# 0003. Backend: Node.js 24 LTS + Fastify 5 + ws, модульный монолит, локальный хостинг

- **Статус:** Accepted
- **Дата:** 2026-10-30
- **Связанные задачи:** FND-005, SRV-001…SRV-009

## Контекст

Backend — точка синхронизации Godot и телефона и хост Game Core (ADR 0002). Нужны REST,
WebSocket, управление сессиями, привязка устройства, проверка сообщений, переподключения,
хранение сессий, логирование. Нагрузка — одна-две сессии на процесс (локальный хостинг).

## Рассмотренные варианты

1. **Node.js + Fastify + ws (TypeScript)** — общий язык с Game Core и мобильным приложением, общие
   zod-схемы, зрелые библиотеки, встроенное логирование (pino), `inject()` для тестов без сети.
2. **Go / Rust** — отличная производительность и бинарная упаковка, но Game Core пришлось бы писать
   на другом языке или поддерживать FFI. Отклонено.
3. **Godot headless как сервер** — нарушает требование тестировать ядро без Godot. Отклонено.
4. **Микросервисы** — нет обоснованной необходимости для MVP. Отклонено.

## Решение

- Node.js **24 LTS** (Maintenance LTS до 30.04.2028; поддерживается Expo SDK 58: ≥ 24.3).
  Переход на Node.js 26 LTS (LTS с 28.10.2026) — отдельная задача после проверки совместимости
  инструментов Expo.
- **Fastify 5** (REST, валидация, `inject`), **@fastify/websocket 11** поверх **ws 8**.
- Модульный монолит: модули `sessions`, `pairing`, `gateway` (WS), `views`, `qr`, `saves`,
  `diagnostics`; Game Core подключается как библиотека.
- Хранение: память процесса + JSON-файлы сохранений в каталоге данных пользователя
  (`HS_DATA_DIR`). База данных не нужна для MVP (сохранение = seed + журнал действий, ADR 0014).
- Логирование: pino (встроен в Fastify), JSON-логи, `sessionId` в каждом записи, без токенов.
- Порт по умолчанию **7420**, привязка к `0.0.0.0` для доступа телефона по LAN.

## Последствия

- Один процесс хостит несколько сессий; масштабирование на облако не требуется для MVP.
- Сетевой доступ телефона зависит от конфигурации LAN и брандмауэра (риск R-04, задача SRV-008).
- Транспорт в LAN — HTTP/WS без TLS в MVP; модель угроз и план перехода на TLS — в ADR 0008.
