# 0017. Следы: закон сохранения улик, полезная нагрузка и уничтожение

- **Статус:** Accepted
- **Дата:** 2026-11-21
- **Связанные задачи:** EVD-001, EVD-002, SIM-005, CNT-004
- **Заменяет / заменён:** —

## Контекст

`@hs/core/evidence` выводит следы (`Trace`) из событий истины по `trace-rules.json`
([scenario-presets.md §5](../../procedural-generation/scenario-presets.md)). Контракт `Trace` в
[modules.md §8](../modules.md) не содержал данных, без которых EVD-002 не построит улику
(`template`, `supports`, `captureMode`), и не определял закон сохранения улик, `requires`,
`destroyedBy` и временные границы — вопросы OQ-14…OQ-17
([open-questions.md](../../planning/open-questions.md)). Владелец разрешил MVP-решения, не
разрушающие существующие контракты.

## Рассмотренные варианты

1. Хранить в `Trace` только ссылку на правило, а `template`/`supports` читать в EVD-002 из правил —
   след проще, но EVD-002 зависит от позиции правила в файле и повторяет подстановки.
2. Переносить полезную нагрузку в `Trace` при выводе следа с подстановкой значений события — след
   самодостаточен и детерминирован; выбран.
3. Закон сохранения проверять при загрузке контента (`CONTENT_SCHEMA_ERROR`) — ломает тестовые
   сценарии без глаголов сокрытия; проверка в `compileTraceRules` совпадает с формулировкой задачи
   («ошибка загрузки правил», `EVIDENCE_RULE_INVALID`); выбрано.

## Решение

**Закон сохранения (OQ-14).** Глаголы сокрытия MVP — `hide`, `destroy`, `stage`
(`CONCEALMENT_VERBS`). `compileTraceRules` требует для каждого из них правило без условий `when`
(отсутствующее или пустое), у которого хотя бы один элемент `produces` не имеет `requires`; иначе —
`EVIDENCE_RULE_INVALID` по пути `traceRules`. Такой элемент всегда даёт вторичный след: его не
подавляют ни условия, ни отсутствие носителя. Перемещение `move` сокрытием не считается.

**Полезная нагрузка (OQ-15).** `Trace` дополнен полями `template`, `supports`, `captureMode`
и (необязательно) `destroyedAt`:

- `supports` — строки правила с подстановкой значений события: `$location` → локация события,
  `$t` → начало события `t`, `$actor` → id участника; строка с `$actor` повторяется для каждого
  различного участника в порядке `actorIds` и отбрасывается, если участников нет. Дубликаты
  удаляются с сохранением порядка. Другие `$`-подстановки отклоняет `compileTraceRules`
  (`EVIDENCE_RULE_INVALID`), поэтому в след не попадает неразрешённый текст.
- `captureMode`: `direct` и отсутствие поля → `auto`, `qr` → `qr` (как в `Clue`).
- `itemId` — носитель: `requires.itemId`; иначе первая цель-предмет события, удовлетворяющая `when`;
  для правила без условий — первая цель-предмет; без целей-предметов поля нет.
- `requires`: след не порождается, если носителя нет в `ItemRegistry` или он уничтожен к
  `availableFrom` (момент уничтожения `≤ availableFrom`). Остальные элементы правила не затронуты.

**Уничтожение.** Событие `destroy` уничтожает свою первую цель-предмет в момент окончания
`t + duration`. У предмета учитывается только первое уничтожение (раньше окончание, затем раньше
начало, затем меньший id события); повторные `destroy` того же предмета игнорируются. След с
`itemId` получает `destroyedBy` (id события) и `destroyedAt`, если уничтожение произошло строго
внутри его жизни: `availableFrom < destroyedAt < decaysAt`. Следы самого события `destroy`
начинаются в момент уничтожения и им не уничтожаются; так как уничтожение всегда позже начала
следа, циклов нет, а у следа не больше одного `destroyedBy`. Следы без `requires` уничтожением
не подавляются — это сохраняет вторичные следы сокрытия при любом журнале. Уничтожение контейнера
не уничтожает его содержимое (MVP). `tracesForEvent` учитывает уничтожение, только если передан
журнал (`truth`); `deriveTraces` — всегда.

**Время (OQ-16).** `availableFrom = t + duration`, `decaysAt = availableFrom + decaysAfter`. След
существует на полуинтервале `[availableFrom, min(decaysAt, destroyedAt))` — `isTraceAvailable`.
`decaysAfter: null` и отсутствие поля равнозначны (нет распада); `0` и отрицательные значения
отклоняет `traceRulesSchema`. Время может быть отрицательным; выход `availableFrom`, `decaysAt`,
`destroyedAt` за безопасные целые — `RangeError` с id события.

**Сопоставление (OQ-17).** Без изменений: правило срабатывает не более одного раза на событие;
все условия `when` проверяются на одной цели-предмете; в `at` — только `$location`.

## Последствия

- EVD-002 строит `Clue` из `Trace` без обращения к правилам: `template`, `supports`, `captureMode`.
- Каждый сценарий, правила которого компилируются движком, обязан иметь правила для `hide`,
  `destroy`, `stage`; `_test_minimal` дополнен ими.
- Перестановка правил по-прежнему меняет id следов.
- Не решено и остаётся на будущие задачи: уничтожение содержимого контейнера, сокрытие через `move`,
  другие подстановки в `at`, порождение следов на каждую подходящую цель (CNT-004 по запросу).
- Обновлены [modules.md §8](../modules.md) и
  [scenario-presets.md §5](../../procedural-generation/scenario-presets.md).
