# 0015. Маршруты NPC с учётом часов доступа

- **Статус:** Proposed
- **Дата:** 2026-11-20
- **Связанные задачи:** SIM-001, WORLD-001
- **Заменяет / заменён:** —

## Контекст

Кратчайший путь по графу учитывает замки переходов. Время входа в помещение может сделать
такой путь недоступным, хотя другой путь приводит к цели раньше. Симуляции нужен момент
начала перехода, чтобы записать ожидание и движение как отдельные шаги.

## Рассмотренные варианты

1. Проверять доступ после выбора кратчайшего пути. Это сохраняет простой вызов графа,
   но пропускает открытые обходы.
2. Добавить поиск по времени прибытия в граф. Он использует те же переходы и правила доступа,
   а симуляция получает время ближайшего шага.

## Решение

Добавить `LocationGraph.nextTimedStep`. При поиске актёр может дождаться открытия в текущем
помещении. Граф возвращает ближайшее ребро выбранного маршрута, время выхода и прибытия.
`SimulationRunner` решает, когда пересчитать план, и исполняет шаги через `TimeSystem`.

## Последствия

- Контракты `path` и `travelTime` сохраняются для существующих вызовов.
- Закрытие ограничивает вход. Актёр, уже находящийся внутри, может остаться или выйти.
- Границы расписания могут прервать ожидание. Начатый переход завершается за полное время ребра.
