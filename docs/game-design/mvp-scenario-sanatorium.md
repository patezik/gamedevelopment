# MVP-сценарий: «Санаторий „Сосновый бор“»

Пресет `sanatorium_winter`. Документ задаёт дизайн; данные — `content/scenarios/sanatorium_winter/`
(задачи CNT-002…CNT-006).

## Сеттинг (рабочее решение для MVP)

Современность: январь 2026 года, приглушённая «аналоговая» хоррор-эстетика (лампы дневного света,
дисковый телефон без гудка, радио с помехами, советские интерьеры здравницы). Смартфон героя
естественен для этого времени. Это рабочее решение владельца по OQ-12, принятое для CNT-002; от него
зависят `preset.time.startDateTime`, пулы имён, тексты биографий, названия предметов и описания
локаций. Перенос вопроса в «Решённые» в
[open-questions.md](../planning/open-questions.md) делается отдельным изменением.

## Завязка

Январь, отдалённый санаторий в сосновом лесу. Метель отрезала дорогу на три дня. Утром в
процедурном корпусе находят тело одного из обитателей санатория. Герой — гость, бывший
следователь, которого администрация просит разобраться до прибытия полиции. Связь с внешним миром —
только через телефон героя, но сигнал… странный.

## Параметры

| Параметр | Значение |
|----------|----------|
| Начало | день 1, 08:00; `startDateTime` — `2026-01-14T08:00:00` |
| Длительность | 3 дня (4320 минут); полиция прибывает в конце дня 3 |
| Персонажей | 7 из 9 архетипов: 4 сотрудника (главврач, медсестра, завхоз, повар; квота 1..1) и 3 гостя из 5 типов (предприниматель, пенсионер, блогер, отставной офицер, родственник бывшего пациента; квота 0..1) |
| Локаций | 12 (холл, столовая, кухня, кабинет врача, процедурный корпус, архив, котельная, номера первого и второго этажа, мансарда, оранжерея, тропа к озеру); не меньше 2 точек интереса в каждой, всего 37 |
| Типы инцидентов | `murder` (шаблоны: отравление, удар с инсценировкой падения, «несчастный случай» в котельной) |
| Мотивы (≥ 5 правил) | наследство, шантаж, ревность, месть за прошлое, сокрытие врачебной ошибки, долг |
| Предыстория | симуляция с дня 0, 08:00 (24 ч до начала игры) |
| Критические события | день 2, 22:00 (`at: 2280`) — отключение электричества; если Static ≥ 50 — день 2, 16:00 (`at: 1920`); возможный вторичный инцидент |
| Концовки | раскрытие, неполное раскрытие, ложное обвинение, время вышло, гибель, безумие |

## Ограничения на виновника (из пресета, не роли)

- Должен иметь доступ к средству (ядовитое вещество — медкабинет/оранжерея; тяжёлый предмет —
  любой; котельная — ключ у завхоза или украденный ключ).
- Должен иметь окно возможности ≥ 20 минут без свидетелей в месте преступления.
- Должен иметь мотив силы ≥ 0,4 по правилам мотивов (или выполнить правило «сокрытие» при
  наличии секрета, который знает жертва).
- Жертва не может быть виновником (в MVP один виновник, без соучастников).

Любой из 6 оставшихся персонажей, удовлетворяющий ограничениям, может стать виновником;
цель seed sweep — каждый архетип становится виновником хотя бы в 5 % прохождений.

## Данные пресета (CNT-002)

Минуты в `criticalEvents` и `deadlines` отсчитываются от начала игры (день 1, 08:00).
Пример `at: 2760` в [scenario-presets.md](../procedural-generation/scenario-presets.md) не
соответствует дню 2, 22:00; в данных используется 2280.

| Файл | Содержимое |
|------|------------|
| `locations.json` | 12 локаций, двусторонние связи; запертые переходы: котельная (из кухни и процедурного корпуса, `it_key_boiler`), архив (из кабинета врача, `it_key_archive`). Часы доступа: кухня 06:00–22:00, кабинет врача 08:00–20:00, процедурный корпус 08:00–21:00, оранжерея 07:00–21:00, тропа к озеру 08:00–17:00; сотрудники по своим архетипам — в любое время |
| `items.json` | 35 предметов: яды (`poison`: дигоксин и морфин в шкафу медикаментов, средство от вредителей и олеандр в оранжерее), тяжёлые предметы (`heavy`, 6 штук), физические ключи, журналы, планшет медсестры и стикер с паролем |
| `archetypes.json` | 9 архетипов, по 8 имён и 8 фрагментов биографии на каждый (72 имени, 72 фрагмента); распорядок покрывает сутки без пропусков и пересечений |
| `relationships.json` | 13 шаблонов отношений с типами из `RelationType`, 18 видов секретов |

Правила данных:

- Ключи — физические предметы (ADR 0016 «Физические ключи для запертых переходов», вносится PR #34):
  ключ котельной у завхоза, ключ архива у главврача. `access` архетипа не создаёт владения.
- У каждого предмета ровно одно начальное размещение. `ownerArchetype` указывают только для
  архетипов с квотой `min ≥ 1`: иначе владелец может отсутствовать в составе, и `ItemRegistry`
  отклонит размещение.
- Предмет, лежащий в локации, указан в `itemIds` точки интереса этой локации.
- Биографии написаны без рода (нет прошедшего времени и кратких прилагательных о самом
  персонаже), потому что имена в пулах обоих родов, а поля пола в схеме нет. Исключение —
  медсестра: пул имён женский по названию архетипа.
- Виды секретов: `will_changed`, `affair`, `embezzlement`, `malpractice`, `falsified_records`,
  `hidden_debt`, `gambling_debt`, `false_identity`, `past_conviction`, `drug_theft`, `addiction`,
  `illegitimate_child`, `terminal_diagnosis`, `insurance_fraud`, `blackmail_material`,
  `hit_and_run`, `secret_investigation`, `land_deal`. Шаблоны `secret_<kind>` ссылаются на тексты
  CNT-005; загрузчик эти ссылки не проверяет.
- Ни один архетип, тег или поле не обозначает виновника или подозреваемого.

### Временный каркас для загрузчика

Загрузчик требует все девять корневых файлов, а `crossCheck` — существующие шаблоны инцидентов и
правила следов для их глаголов. Поэтому CNT-002 содержит минимальные согласованные данные
`motives.json` (5 правил), `crimes.json` (3 шаблона), `trace-rules.json` (11 правил для `take`,
`poison`, `strike`, `tamper`, `stage`, `hide`, `destroy`) и `deduction-rules.json` (4 правила).
Это каркас, а не результат CNT-003/CNT-004: требования, планы, силы мотивов, следы и правила
дедукции будут пересмотрены там. Правила следов используют только `$location` в `at` и
глаголы формата `verbSchema`, совместимые с EVD-001. `crimes.json` и `motives.json` заменены
данными CNT-003 (следующий раздел); `trace-rules.json` и `deduction-rules.json` остаются
каркасом до CNT-004.

## Шаблоны преступлений и правила мотивов (CNT-003)

### Как читаются поля шаблона

Схему `crimesSchema` CNT-003 не меняет. Стадии IncidentSelection (GEN-006) и PlotPlanning
(GEN-007) ещё не реализованы, поэтому данные опираются на такое чтение полей:

- `requires.locationTags` — место деяния (`$location`) имеет **все** перечисленные теги.
- `requires.means` — предмет с тегом `itemTag`, а при заданном `itemId` — именно этот предмет.
  Виновник берёт его в доступной ему локации или крадёт у владельца из состава.
- `requires.minWindowMinutes` — окно в месте деяния без бодрствующих свидетелей. В него
  укладываются все шаги, кроме добычи средства (`before`), которая происходит раньше и в другом
  месте.
- `requires.traits` — условия на черты личности виновника в форме правил мотивов:
  `{ "<черта>": { "gt": x } }` или `{ "<черта>": { "lt": x } }`. Пустой объект — без условий.
- `plan` — ровно один смертельный шаг `act` (`poison`, `strike` или `tamper`). `before` и
  `after` задают порядок, `duration` — минуты. `optional: true` — шаг нужен не всегда: в
  `boiler_accident` виновник добывает и прячет ключ, только если ключ не его.
- `deathDelayMinutes` — только у отложенной смерти (`poison`, `tamper`): жертва умирает в этом
  интервале после деяния. Для `tamper` жертва должна оказаться на месте в этот интервал.

### Шаблоны

| Шаблон | Средство | Место | Окно | План, минуты | Смерть | Личность |
|--------|----------|-------|------|--------------|--------|----------|
| `poisoning` | `poison`: дигоксин и морфин (шкаф медикаментов), средство от вредителей и олеандр (оранжерея) | `private` + `main_building`: кабинет врача, номера 1–3 | 20 | take 5 → poison 10 → hide 5 | через 60–180 | — |
| `staged_fall` | `heavy`: кочерга, бюст, молоток, гантель, газовый ключ, лопата | `outdoor` + `hazard`: тропа к озеру | 20 | take 3 → strike 2 → stage 10 → hide 5 | сразу | `courage` > 0,3 |
| `boiler_accident` | `it_key_boiler` | `service` + `hazard`: котельная | 30 | (take 2) → tamper 15 → stage 10 → (hide 3) | через 30–120 | — |

- `poisoning`: архив исключён тегом `main_building` — он заперт и там никто не ест и не пьёт;
  процедурный корпус (`semi_private`) — место процедур при персонале.
- `staged_fall`: в каркасе CNT-002 место требовало `residential` и `hazard`, но ни у одной
  локации нет обоих тегов. Тропа к озеру — обледенелые ступени и мостки, изолированное место.
  Котельная (тоже `hazard`) исключена тегом `outdoor`: она заперта, а план не добывает ключ.
- `boiler_accident`: по распорядку в котельной регулярно бывает только завхоз (отдых и сон),
  поэтому жертвой на практике становится он, если генератор не «изогнёт» расписание жертвы.
  Ключ — у завхоза; любой другой виновник его крадёт.
- Шаблоны не называют виновника: архетипы в них не упоминаются, а ограничения касаются только
  средства, места, окна и личности.

### Правила мотивов

У направленных отношений `from` — сотрудник, должник или шантажист. Секрет правила объявлен в
том же шаблоне отношений, что и отношение, поэтому SocialGen может породить их вместе.

| Правило | Отношение (шаблон) | Секрет | База | Надбавки | Макс. |
|---------|--------------------|--------|------|----------|-------|
| `inheritance` | `parent`: $v → $c (`rel_family_parent`) | `will_changed` о $v, знает $c | 0,45 | honesty < 0,4: +0,2; agreeableness < 0,4: +0,1 | 0,75 |
| `blackmail` | `blackmail`: $v → $c (`rel_leverage`) | `blackmail_material` о $c, знает $v | 0,5 | neuroticism > 0,6: +0,15; courage > 0,7: +0,1 | 0,75 |
| `jealousy` | `spouse`: $c — $v (`rel_married_guests`) | `affair` о $v, знает $c | 0,45 | impulsivity > 0,6: +0,2; neuroticism > 0,6: +0,1 | 0,75 |
| `revenge` | `past_conflict`: $c — $v (`rel_grievance_accident`) | `hit_and_run` о $v, знает $c | 0,5 | agreeableness < 0,3: +0,2; courage > 0,8: +0,1 | 0,8 |
| `malpractice_coverup` | — | `malpractice` о $c, знает $v (`rel_leverage`, `rel_grievance_malpractice`) | 0,5 | honesty < 0,4: +0,15; neuroticism > 0,6: +0,1 | 0,75 |
| `debt` | `debt`: $c → $v (`rel_money_owed`) | `hidden_debt` о $c, знает $v | 0,4 | impulsivity > 0,6: +0,15; honesty < 0,4: +0,1 | 0,65 |

- `inheritance` ссылается на `parent` от жертвы к виновнику: шаблона `child` в
  `relationships.json` нет, а граф отношений строит обратное ребро сам.
- `debt` добавлен потому, что без него шаблон `rel_money_owed` и его секреты не дают мотива, а
  это единственный мотив постоянного персонала против главврача.
- `malpractice_coverup` — правило «сокрытия»: отношение не требуется, достаточно, чтобы жертва
  знала о врачебной ошибке виновника.
- Отношения `romance`, `friendship`, `rivalry`, `employment` и `sibling` мотивов не дают: их
  секреты остаются для ложных следов и показаний.
- Каждая надбавка достижима хотя бы для одного архетипа в роли $c; сила остаётся в 0…1.

### Проверка выполнимости

`packages/core/src/content/sanatorium-incidents.test.ts` проверяет данные статически, на уровне
архетипов:

- средства, места и черты существуют, план упорядочен и укладывается в окно;
- для каждого шага плана есть правило следа, срабатывающее на его цель;
- правила мотивов ссылаются на существующие отношения и секреты одного шаблона;
- для каждого шаблона в каждом из 10 возможных составов найдётся жертва с выполнимым
  виновником: мотив может сработать, средство досягаемо, личность подходит, а окно без
  бодрствующих свидетелей есть, если изменить только расписание виновника;
- каждый из 9 архетипов выполним как виновник хотя бы в одном шаблоне.

Ограничения: отношения и секреты — возможности шаблонов, а не результат SocialGen;
присутствие берётся только из распорядка, а черты — из диапазонов архетипа. Проверка на 500 seed
сгенерированных миров возможна только после GEN-006 (IncidentSelection).

Замечания для следующих задач:

- `rel_leverage` допускает секрет `malpractice` о поваре, предпринимателе и офицере. Выбрать
  субъекта секрета осмысленно должна SocialGen (GEN-004).
- Правило дедукции `motive_from_secret` покрывает только секреты о жертве, известные виновнику.
  Для `blackmail`, `malpractice_coverup` и `debt` нужен парный случай — секрет о виновнике,
  известный жертве (CNT-004).

## Обязательная роль телефона в сценарии

- Улики фото (следы, пятна, записи в журнале процедур) — `captureMode: qr`.
- Номера персонажей выдаются в разговорах; гости переписываются с героем.
- Скрытые файлы на «рабочем планшете» медсестры доступны через Files при найденном пароле.
- Static проявляется на телефоне; при отключении электричества заряд телефона становится критичным.
