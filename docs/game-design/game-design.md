# Game Design Document

Документ описывает игровой опыт и правила на уровне дизайна. Технические контракты — в
[modules.md](../architecture/modules.md). Числа здесь — стартовые значения для баланса (INT-004).

## 1. Структура прохождения (run)

1. **Выбор сценария-пресета** (в MVP — один: «Санаторий „Сосновый бор“»). Seed — случайный или
   введённый вручную (для повторения и обмена).
2. **Подключение телефона.** Godot показывает QR привязки, игрок сканирует его в companion-приложении.
   Без подключённого телефона начать расследование нельзя (MVP).
3. **Вступление.** Завязка из пресета + сгенерированные обстоятельства (кто пострадал, кто нашёл).
4. **Расследование** — основной цикл (раздел 2) до одного из исходов.
5. **Финал** — концовка, разбор: что было на самом деле (показ истины после завершения),
   статистика, seed.

Roguelike-элементы: каждое прохождение — новый мир; смерть/безумие/провал завершают прохождение;
одно активное сохранение («suspend»). Мета-прогрессия — после MVP (OQ-04).

## 2. Основной цикл

```
выбрать действие (видна стоимость во времени) → время идёт → мир реагирует →
новые сведения (улики, показания, сообщения на телефон) → обновить гипотезы → …
```

### Действия игрока и стоимость (стартовые значения)

| Действие | Где | Минуты | Примечание |
|----------|-----|--------|------------|
| Переход между соседними локациями | desktop | 3–15 | из графа локаций; в темноте ×1,5 без фонаря |
| Осмотреть локацию | desktop | 15 | открывает точки интереса |
| Изучить точку/предмет | desktop | 5 | может открыть улику |
| Сфотографировать улику (скан QR) | phone | 2 | только для улик `captureMode: qr` |
| Поговорить (тема) | desktop | 10 | показания по теме |
| Допросить (предъявить улику/противоречие) | desktop | 20 | меняет отношение, может вскрыть ложь |
| Позвонить | phone | 5 + длительность разговора | только известным контактам |
| Написать сообщение | phone | 2 | ответ приходит позже по симуляции |
| Изучить документ / файл | desktop/phone | 10 | |
| Вскрыть замок | desktop | 20 (+10 при неудаче) | нужна отмычка; шумно — NPC могут услышать |
| Использовать предмет | desktop | 5 | |
| Отдых | desktop | 60 / 120 / 240 | восстанавливает усталость и рассудок, мир идёт дальше |
| Ждать | desktop | 15–120 | чтобы застать персонажа |

Стоимость всегда показывается **до** подтверждения. Модификаторы: усталость (> 70 → +25 %),
низкий рассудок (≤ 3 → разговоры +5 мин), травма (здоровье ≤ 3 → перемещения +50 %).

## 3. Персонажи и общение

- Все персонажи сценария — участники мира (персонал, гости, местные), 6–8 в MVP.
- У каждого есть расписание; найти нужного человека — часть игры. Карта в телефоне показывает,
  где персонажа **видели** (по данным игрока), а не где он сейчас.
- Разговор — выбор темы: «где вы были [время]», «что вы знаете о [персонаж]», «что это [улика]»,
  «расскажите о себе». Ответы генерируются из знаний персонажа: правда, ошибка памяти или ложь.
- Допрос — предъявление улики или противоречия. Если ложь опровергнута, персонаж может признать
  её, сменить версию или замкнуться (зависит от личности). Давление повышает настороженность.
- Персонажи помнят интерес игрока: частые вопросы о скрываемой теме делают их осторожнее
  (виновник может начать прятать улики, невиновный с секретом — тоже).

## 4. Улики, гипотезы, подозрения

- **Улики** бывают физические, документальные, цифровые и свидетельские. Каждая
  подтверждает одно или несколько утверждений: мотив, средство, возможность, присутствие, алиби.
- **Подозреваемые не назначаются системой.** Доска дела показывает «персон интереса» —
  персонажей, связанных хотя бы с одной найденной уликой, — и игрок сам отмечает уровень
  подозрения (нет / возможно / главный подозреваемый).
- **Противоречия** подсвечиваются, когда у игрока есть обе части (показание и опровергающий факт).
- **Хронология** на доске собирается из найденных фактов о времени и местах.

## 5. Обвинение и исходы

Обвинение — необратимое действие (подтверждение дважды). Игрок указывает обвиняемого, мотив,
средство, возможность и прикладывает улики из дела.

| Исход | Условие | Последствия |
|-------|---------|-------------|
| **Раскрытие** | Верный обвиняемый, доказаны мотив + средство + возможность | Лучшая концовка |
| **Неполное раскрытие** | Верный обвиняемый, доказано меньше трёх элементов | Виновник отпущен «за недостатком улик»; горькая концовка |
| **Ложное обвинение** | Неверный обвиняемый | Персонажи реагируют; виновник действует свободнее; если время осталось — расследование продолжается с штрафом к доверию (одна попытка), иначе плохая концовка |
| **Время вышло** | Конец сценария без обвинения | Концовка по состоянию угрозы |
| **Гибель** | Здоровье 0 | Концовка смерти |
| **Безумие** | Рассудок 0 | Концовка «сигнал победил» |

## 7. Роль телефона (обязательная)

Телефон — не дублирующий интерфейс, а носитель части игры:

- **Камера** — единственный способ зафиксировать улики `captureMode: qr` (в MVP — не менее 30 %
  ключевых улик каждого расследования; правило проверяется валидатором).
- **Галерея/файлы** — детали улик (увеличение фото, метаданные, скрытые файлы с паролями).
- **Контакты/звонки/сообщения** — персонажи дают номера; звонок экономит переход, но не всё
  можно спросить по телефону; NPC сами пишут игроку (наводки, угрозы, слухи).
- **Карта** — открытые локации и наблюдения о местонахождении персонажей.
- **Заметки** — автоматический журнал + заметки игрока.
- **Помехи** — при росте Static телефон начинает «сбоить»: см. survival-horror.md.

## 8. Тон и подача

Мрачный, приглушённый, без натурализма ради шока. Визуально — статичные иллюстрированные локации
с ограниченной палитрой и дизерингом, интерфейс «досье». Звук — эмбиент, тишина, редкие стингеры.
Текст — сдержанный, на русском (локализация — QA-003).
