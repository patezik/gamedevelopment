# Конвейер процедурной генерации расследования

Решение — [ADR 0006](../architecture/adr/0006-generation-pipeline.md). Код — `@hs/generator`.

## 1. Принцип

Сначала создаётся **мир с людьми**, затем в этом мире выясняется, **кто мог** совершить
преступление, и лишь затем выбирается, **кто совершил**. Улики и показания не придумываются
отдельно — они следуют из событий истины и знаний персонажей.

## 2. Стадии

Каждая стадия — чистая функция `(input, ctx) → output` с собственным подпотоком
`ctx.rng = root.fork("gen/<stage>")` ([ADR 0004](../architecture/adr/0004-determinism.md)).

| # | Стадия | Вход | Выход | Ключевые правила |
|---|--------|------|-------|------------------|
| 1 | **WorldGen** | пресет | `WorldState`: локации, связи, предметы, освещение, доступ | Варианты из пресета (какие комнаты заперты, где лежат предметы) |
| 2 | **CastGen** | пресет, мир | `Character[]` | Архетипы по квотам пресета; личность — сэмпл распределений архетипа; имена из пулов; биографии из тегированных фрагментов |
| 3 | **SocialGen** | персонажи | `RelationshipGraph`, `Secret[]` | Шаблоны отношений (родство, роман, долг, вражда, служебные); согласованность (симметрия, исключения); у каждого ≥ 1 секрет |
| 4 | **ConflictGen** | отношения, секреты | `MotiveCandidate[]` для всех упорядоченных пар | Правила мотивов из пресета: условие на отношения/секреты → тип и сила мотива |
| 5 | **IncidentSelection** | мотивы, мир | `IncidentPlan`: тип, шаблон преступления, жертва, **виновник** | См. §3 |
| 6 | **PlotPlanning** | план, расписания | действия виновника (подготовка, подход, деяние, сокрытие, алиби) | Окно возможности встраивается в расписание; если нужно — расписание «изгибается» правдоподобной причиной |
| 7 | **HistorySimulation** | всё выше | `TruthLog` предыстории, знания персонажей | Character Simulation от начала предыстории до `t = 0`; действия виновника исполняются как цели с высоким приоритетом |
| 8 | **EvidenceGen** | журнал, правила следов | `Trace[]`, `Clue[]` | `TraceRule` по глаголам; закон сохранения улик; распределение `captureMode` |
| 9 | **TestimonyGen** | знания, секреты | `LiePolicy` каждого, банк тем | Ложь только при мотиве скрывать |
| 10 | **RedHerrings** | секреты невиновных | дополнительные следы их (реальных) проступков | Это истинные события, не фальшивки |
| 11 | **Validation** | расследование | `ValidationReport` | [validation.md](../investigation/validation.md); при ошибке — ремонт/перегенерация |
| 12 | **Packaging** | всё | `Investigation` + `investigationHash` + `GenerationReport` | Сериализуемый объект для сервера |

## 3. Выбор виновника (IncidentSelection)

```
victimCandidates = персонажи, удовлетворяющие ограничениям пресета на жертву
для каждой жертвы v (взвешенно по «заметности» и числу мотивов против неё):
  для каждого шаблона преступления T, разрешённого пресетом:
    feasible = []
    для каждого персонажа c ≠ v (ВСЕ участники мира, не список подозреваемых):
      motive  = max силы MotiveCandidate(c → v)               ≥ preset.minMotive
      means   = доступ c к средству T (access grants, локации, предметы) или способ получить
      opport  = в расписании c найдётся окно ≥ T.minWindow в локации, доступной для T,
                которое можно сделать «без свидетелей» изгибом не более 1 блока расписания
      capable = требования T к личности/физическим данным (например, impulsivity для «удара»)
      если всё выполнено → feasible.push({ c, score = motive · w1 + opportunityQuality · w2 + personalityFit · w3 })
    если feasible не пусто → выбрать c = rng.weighted(feasible по score^γ) ; γ = 0.7 сглаживает доминирование
```

Свойства: (1) нет заранее заданных подозреваемых; (2) любой персонаж, у которого в этом мире
сложились мотив, средства и возможность, может стать виновником; (3) параметр `γ` и пороги
контролируются seed sweep по энтропии распределения виновников.

## 4. Отчёт генерации

`GenerationReport { seed, generatorVersion, attempts: AttemptReport[], timingsMs: Record<stage, number>,
feasibleCulpritCount, chosen: { victimArchetype, culpritArchetype, template, motiveType } }` —
**не** отдаётся клиентам (содержит истину), сохраняется в отчётах sweep и debug-логах.

## 5. Расширяемость

- Новый сценарий = новый пресет (данные). Если пресету нужна новая механика (новый глагол, тип
  следа, тип мотива) — она добавляется в словари ядра отдельной задачей, а не в пресет.
- Новая стадия добавляется в список стадий с собственным подпотоком; существующие результаты
  не меняются, но `GENERATOR_VERSION` увеличивается.
