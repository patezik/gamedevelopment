# Investigation Engine: персонажи, виновники, подозреваемые, улики, дедукция

## 1. Три разных сущности

| Сущность | Где живёт | Кто знает | Смысл |
|----------|-----------|-----------|-------|
| **Character** | `@hs/core/characters` | все системы | Участник мира. Не имеет роли «подозреваемый» или «виновник». |
| **Culprit** | `TruthModel.incident.culpritIds` | только сервер (истина) | Фактический виновник этого прохождения. |
| **Suspect** | `PlayerKnowledge.suspicions` | игрок | Персонаж, которого **игрок** подозревает. Создаётся отметкой игрока на доске дела. |

Дополнительно система вычисляет **Person of Interest** — персонажа, с которым у игрока есть
хотя бы одна связь из найденных сведений. Это подсказка интерфейса, а не обвинение;
вычисляется только из `PlayerKnowledge` и не читает истину.

## 2. Сведения игрока (`PlayerKnowledge`)

- `clues` — найденные улики (`DiscoveredClue { clueId, discoveredAt, location, captured: boolean }`).
- `statements` — услышанные показания (`Statement` без поля `veracity`).
- `contacts` — известные контакты персонажей.
- `journal` — хронологический журнал (автоматические заметки).
- `suspicions` — отметки игрока `{ characterId, level: "none" | "possible" | "prime", note }`.

## 3. Утверждения (Claims) и дедукция

Каждая улика и показание поддерживает **утверждения**:

| Claim | Смысл | Примеры поддержки |
|-------|-------|-------------------|
| `presence(c, loc, interval)` | c был в loc в интервале | следы обуви, показание свидетеля, журнал ключей |
| `opportunity(c)` | у c было окно для инцидента | presence в месте и времени инцидента + отсутствие свидетелей |
| `means(c)` | у c был доступ к орудию/средству | доступ к медкабинету, отпечатки на предмете |
| `motive(c, victim)` | у c была причина | письмо с угрозой, долговая расписка, рассказ о ссоре |
| `alibi(c, interval)` | c был в другом месте | подтверждённое показание другого персонажа, запись в журнале |
| `contradiction(statement, fact)` | показание опровергается фактом | показание «спал у себя» vs следы у процедурной |

`DeductionRules` (данные, не код) задают, какие сочетания утверждений «устанавливают» элемент
дела. Например: `opportunity(c)` установлен, если есть `presence(c, incident.location, I)`,
где `I` пересекается с окном инцидента, и нет подтверждённого `alibi(c, I')`, покрывающего окно.

> Важно: окно инцидента игрок узнаёт из улик (время смерти от осмотра тела, показания).
> Дедукция оперирует **известным игроку** окном, а не истинным.

## 4. Противоречия

`detectContradictions` сравнивает показания с установленными фактами. Противоречие появляется,
только когда у игрока есть обе стороны. Не все противоречия указывают на виновника: невиновные
лгут о своих секретах (роман, кража, долг). Это — естественные ложные следы, порождённые
истиной, а не подброшенные «красные селёдки».

## 5. Дело и обвинение

```ts
interface CaseFile { accusedIds: CharacterId[]; motive?: ClaimRef; means?: ClaimRef; opportunity?: ClaimRef; evidence: ClueId[] }
```

`evaluateAccusation` возвращает:

```ts
interface AccusationOutcome {
  correct: boolean;                          // множество accusedIds == culpritIds
  proven: { motive: boolean; means: boolean; opportunity: boolean };   // подтверждены приложенными уликами
  endingId: "solved" | "partial" | "wrong_accusation";
  consequences: ConsequenceRef[];            // реакции NPC, Static, продолжение игры
}
```

Сервер отклоняет улики-галлюцинации и улики, которых нет в `PlayerKnowledge`.

## 6. Реакции мира

- Вопросы игрока о теме → `wariness` у персонажей, для которых тема чувствительна.
- Ложное обвинение → обвиняемый и его близкие отказываются говорить; доверие остальных падает;
  виновник получает «свободу действий» (сокрытие улик, возможный вторичный инцидент).
- Верное обвинение без доказательств → виновник пытается скрыться/уничтожить оставшиеся улики.

## 7. Отображение

- Godot: доска дела (улики, показания, противоречия, персоны интереса, хронология, отметки).
- Телефон: заметки (журнал), галерея и файлы (детали улик), карта (места и наблюдения).
