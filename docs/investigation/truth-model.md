# Truth Model — объективная истина расследования

Решение — [ADR 0005](../architecture/adr/0005-truth-and-knowledge.md). Интерфейс — [modules.md §5](../architecture/modules.md).

## 1. Назначение

Truth Model отвечает на вопросы: **что произошло, кто участвовал, кто ответственен, почему,
когда, где, какие действия совершались и какие следы они оставили.** Все остальные системы
(улики, показания, документы, сообщения, хронология, поведение NPC) порождаются из неё или
дописывают в неё новые события. Ни одна система не «придумывает» факт мимо Truth Model.

## 2. Состав

```
TruthModel
├── TruthLog: TruthEvent[]          — append-only, чтение по времени и номеру события
├── IncidentRecord                  — тип, жертвы, culpritIds, мотив, средство, ключевые события, окно
├── SecretRegistry                  — секреты: факт + кто знает (начальное состояние знаний)
└── индексы: presence по персонажам, possession по предметам, facts по kind
```

### TruthEvent

| Поле | Смысл |
|------|-------|
| `id` | `ev_<n>`, порядковый номер |
| `t`, `duration` | начало и длительность в игровых минутах |
| `verb` | из словаря: `move`, `stay`, `talk`, `take`, `give`, `hide`, `destroy`, `poison`, `strike`, `stage`, `write`, `read`, `call`, `message`, `lock`, `unlock`, `observe`, `sleep`, `work`, … |
| `actorIds` | кто совершил |
| `location` | где |
| `targets` | на что/кого направлено (`EntityRef`: персонаж, предмет, документ, локация) |
| `causes` | события-причины (план виновника, реакция на событие) |
| `facts` | факты, ставшие истинными в результате (см. ниже) |
| `traceIds` | порождённые следы (заполняет Evidence System) |
| `visibility` | `public` (видно присутствующим), `covert` (скрытно — увидеть может только внимательный свидетель), `private` (без свидетелей по определению) |

`append` назначает порядковый `ev_<n>`, копирует входные данные и замораживает событие со всеми
вложенными полями. `events()` возвращает события по возрастанию игровой минуты, при равенстве —
по номеру события. `causalChain(id)` возвращает уникальные идентификаторы всех известных причин
в том же порядке. Ссылки на события и инварианты мира проверяет TRUTH-003.

`Presence` и `Possession` строятся из фактов `at` и `possessed` соответственно. `whereWas`
возвращает `in_transit` в разрывах между интервалами присутствия. `whoWasAt` учитывает
пересечение полуоткрытых интервалов. `facts({ kind, pattern })` фильтрует факты по типу и шаблону.

`IncidentRecord.motive` ссылается на `FactId` факта о мотиве, `culpritIds` поддерживает несколько
идентификаторов. `serialize()` записывает инцидент и события в порядке добавления, чтобы
`TruthModel.deserialize()` мог восстановить индексы и последовательность идентификаторов.

### Словарь фактов (`Fact`)

```ts
type Fact =
  | { kind: "at"; who: CharacterId; where: LocationId; interval: Interval }
  | { kind: "did"; who: CharacterId; verb: Verb; target?: EntityRef; at: GameMinutes; where: LocationId }
  | { kind: "possessed"; who: CharacterId; item: ItemId; interval: Interval }
  | { kind: "relation"; a: CharacterId; b: CharacterId; relType: RelationType; since?: GameMinutes }
  | { kind: "motive"; who: CharacterId; against: CharacterId; motiveType: MotiveType; basis: FactId[] }
  | { kind: "state"; entity: EntityRef; property: string; value: string | number | boolean; interval: Interval };
```

Факты — **пропозиции**, которыми оперируют знания персонажей (`Belief.proposition`), показания
(`Statement.proposition`) и утверждения расследования (`Claim`). Единый словарь — основа
согласованности.

Схемы и типы доступны из `@hs/core/truth`. `Verb` допускает новые идентификаторы в `snake_case`.
`EntityRef` хранит пару `{ kind, id }`. Границы интервала задаются целыми игровыми минутами,
включая отрицательные минуты предыстории. Интервал полуоткрытый: `[from, to)`.

`factId(fact)` вычисляет `hashId("f", canonicalJson(fact), 16)` после удаления отсутствующих
необязательных полей. Порядок ключей объектов на идентификатор не влияет.

`Proposition` использует структуру `Fact`. В `PropositionPattern` обязателен `kind`, остальные поля
можно опустить или заменить на `{ var: "name" }`. `matchProposition` возвращает карту подстановок
при совпадении и `null` иначе. Повторное имя переменной требует совпадения значений по структуре.

## 3. Время жизни

1. **Генерация** (стадии PlotPlanning, HistorySimulation) создаёт предысторию до `t = 0` (отрицательные
   времена допустимы для предыстории: `t < 0`) и `IncidentRecord`.
2. **Игра:** симуляция NPC и действия игрока дописывают события с `t ≥ 0`. Действия игрока тоже
   являются событиями истины (актор `player`) — NPC могут их наблюдать.
3. **Финал:** после завершения игры клиенту может быть показан «разбор» — проекция `IncidentRecord`
   и ключевых событий (`TruthRecap`), это единственный легальный выход истины к клиенту.

## 4. Инварианты (проверяются `checkTruthInvariants`)

1. Персонаж в каждый момент в одной локации или «в пути» (нет пересекающихся интервалов `at`).
2. Перемещение между локациями не быстрее времени из графа.
3. Причина раньше следствия (`causes[i].t + causes[i].duration ≤ e.t`).
4. Предмет в каждый момент у одного владельца/в одном месте.
5. Мёртвый персонаж не совершает действий после времени смерти.
6. Событие с `visibility: public` фиксирует наблюдения всех присутствующих (иначе — ошибка
   симуляции знаний).
7. Каждое `IncidentRecord.keyEventIds` существует, и среди его акторов есть хотя бы один `culpritId`.

### Проверка

`checkTruthInvariants(tm, world, options?)` возвращает `InvariantViolation[]`: номер инварианта,
стабильный код, идентификаторы событий (сначала событие, в котором проявилось нарушение, затем
события, с которыми оно конфликтует), необязательные субъект (`EntityRef`) и минуту, сообщение.
Нарушения сгруппированы по номеру инварианта, внутри группы следуют отсортированным
идентификаторам персонажей и предметов и хронологическому порядку журнала. Из мира нужны
`locations.travelTime` и `items.locate`/`items.history` (`InvariantWorld` — часть `WorldState`).

| № | Коды | Что проверяется |
|---|------|-----------------|
| 1 | `PRESENCE_OVERLAP`, `ACTOR_ELSEWHERE` | Интервалы `at` одного персонажа в разных локациях не пересекаются; повтор одной локации допустим. Актор события находится в `location` события на всём отрезке `[t, t + max(duration, 1))`, если факты `at` вообще помещают его куда-либо в это время. «В пути» и отсутствие сведений нарушением не считаются. События `move` пропускаются: их локация — начало или конец пути. |
| 2 | `TRAVEL_TOO_FAST`, `TRAVEL_NO_ROUTE`, `TRAVEL_UNKNOWN_LOCATION` | Между соседними непересекающимися пребываниями в разных локациях проходит не меньше `travelTime` по направленным связям. Замок открыт, если персонаж держит ключ в окне поездки (от последней минуты в исходной локации до первой минуты в новой) по фактам `possessed` или по реестру предметов. |
| 3 | `CAUSE_UNKNOWN`, `CAUSE_SELF`, `CAUSE_NOT_BEFORE_EFFECT`, `CAUSE_CYCLE`, `ITEM_MOVE_UNKNOWN_CAUSE`, `ITEM_MOVE_BEFORE_CAUSE` | Причина существует, не совпадает с самим событием и заканчивается не позже начала следствия. Цикл возможен только из мгновенных событий одной минуты и сообщается один раз. Перемещение предмета (`ItemMove.cause`) ссылается на существующее событие и происходит не раньше его начала. |
| 4 | `ITEM_HOLDER_OVERLAP`, `ITEM_PLACEMENT_CONFLICT`, `ITEM_UNKNOWN` | Интервалы `possessed` одного предмета у разных персонажей не пересекаются. На всём интервале владения реестр помещает предмет к этому персонажу — напрямую или через цепочку контейнеров с учётом их собственной истории; сообщается первая минута расхождения. Минуты до начала реестра не проверяются. Предмет из `possessed` должен быть в реестре. |
| 5 | `ACTION_AFTER_DEATH`, `ACTION_SPANS_DEATH` | См. «Смерть». |
| 6 | — | Не проверяется, см. ниже. |
| 7 | `KEY_EVENT_UNKNOWN`, `KEY_EVENT_WITHOUT_CULPRIT` | Каждое ключевое событие есть в журнале, и среди его `actorIds` есть `culpritId`. |

Реестр предметов не перечисляет свои предметы, поэтому история и ключи проверяются для
предметов, которые упоминает истина (факты `possessed` и `did`, цели событий). Ключ, который
персонаж получил только из контента и который истина нигде не упоминает, не учитывается.

**Смерть** записывается фактом `{ kind: "state", entity: { kind: "character", id }, property:
"alive", value: false, interval }`. Время смерти — `interval.from` самого раннего такого факта;
смерть необратима, и конец интервала её не отменяет. Действие — участие в `actorIds` события
или факт `did` с этим `who`. Действие с началом в минуту смерти или позже даёт
`ACTION_AFTER_DEATH`, начатое раньше и продолжающееся после неё — `ACTION_SPANS_DEATH`.
Событие, в котором записан факт смерти, может иметь умирающего актором (например, `collapse`).
Цель чужого действия, присутствие (`at`) и владение не являются действиями: тело остаётся в
локации, вещи — при нём. Другие состояния (`conscious`, `alive: true`) смертью не считаются.

**Инвариант 6 пока не проверяется.** Наблюдения — это `Belief(source: observed)` в
`KnowledgeStore` персонажей ([character-simulation.md §4](../simulation/character-simulation.md)).
Пара `(tm, world)` их не содержит, а модуль `truth` не может зависеть от `knowledge`
([modules.md](../architecture/modules.md)). Метка `visibility: public` сама по себе наблюдений не
доказывает. Как проверять инвариант после KNOW-001 и SIM-002 — вопрос
[OQ-13](../planning/open-questions.md).

**Debug-режим.** `assertInvariants(tm, world, options?)` бросает `TruthInvariantError`
(`TRUTH_INVARIANT_VIOLATION`) со списком нарушений. `withInvariantChecks(tm, world, { enabled })`
возвращает `TruthWriter`, который после каждого `append` проверяет журнал. Флаг передаёт
вызывающий код: ядро не читает окружение и не хранит глобальный режим. Выключенный писатель
только вызывает `append`. После записи проверка идёт с `incremental: true`. Ссылки на ещё не
записанные `ev_<n>` (ключевые события, причины, причины перемещений предметов) считаются
ожидаемыми. Владение из последнего события ещё не сверяется с реестром, потому что перемещению
в реестре нужен идентификатор, который возвращает `append`. Это владение проверяется после
следующей записи и при полной проверке. Нарушившее инвариант событие остаётся в журнале
(append-only), а `TruthInvariantError.eventId` указывает на него. Каждая запись запускает полную
проверку, поэтому режим предназначен для разработки и тестов.

## 5. Связь с другими системами

| Система | Как использует истину |
|---------|-----------------------|
| Character Simulation | пишет события; формирует наблюдения присутствующих |
| Knowledge | начальные знания из `SecretRegistry`; наблюдения → убеждения |
| Evidence | `TraceRule` по `verb` → следы → улики со ссылкой `sourceEventId` |
| Investigation | **только** `evaluateAccusation` читает `IncidentRecord` |
| Validator | полный доступ: решаемость, инварианты, ложь |
| Phone | сообщения NPC — следствие событий `message` / `call` в истине |

## 6. Debug-доступ

При `HS_DEBUG_TRUTH=1` сервер отдаёт `GET /api/v1/sessions/:id/debug/truth` (только с
`desktopToken`) — полный журнал. Используется в разработке и при разборе багов; в релизных сборках
флаг игнорируется.
