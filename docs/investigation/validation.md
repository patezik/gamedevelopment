# Валидация процедурных расследований

Валидатор (`@hs/validator`) — обязательный шлюз генерации ([ADR 0006](../architecture/adr/0006-generation-pipeline.md))
и инструмент массовой проверки пресетов.

## 1. Проверки

| ID | Проверка | Severity | Как |
|----|----------|----------|-----|
| `V-TRUTH-INV` | Инварианты Truth Model | error | `checkTruthInvariants` |
| `V-TIMELINE` | Корректность хронологии: события внутри сценария, расписания без дыр, перемещения выполнимы | error | проход по журналу и расписаниям |
| `V-CULPRIT-PROVABLE` | Виновник доказуем: достижимые улики устанавливают мотив, средство и возможность | error | солвер (§2) |
| `V-UNIQUE` | Единственность: каждый другой персонаж исключается хотя бы одним достижимым оправдывающим утверждением (алиби, нет средства, нет доступа) | error | солвер |
| `V-LIES-BREAKABLE` | Каждая ложь, мешающая решению (ложное алиби виновника, ложь, бросающая подозрение), опровергается достижимым фактом | error | анализ показаний |
| `V-TESTIMONY` | Правдивые показания согласуются с истиной; ошибки памяти в пределах `fuzzMinutes` | error | сравнение с истиной |
| `V-REACHABLE` | Все обязательные улики достижимы: локации доступны, предусловия выполнимы, нет циклических предусловий | error | граф обнаружения |
| `V-TIME-FEASIBLE` | Существует план действий, решающий дело за ≤ 70 % длительности сценария | error | планировщик (§3) |
| `V-REDUNDANCY` | Каждый элемент дела (мотив/средство/возможность) поддержан ≥ 2 независимыми путями | warning (error для MVP-пресета) | минимальный разрез |
| `V-CLEANUP` | После пассивной симуляции сокрытия (игрок бездействует) дело остаётся решаемым до момента `t_safe` ≥ 25 % длительности | error | прогон симуляции без игрока |
| `V-PHONE-REQUIRED` | ≥ 30 % обязательных улик имеют `captureMode: qr` | error | подсчёт |
| `V-HALLUCINATION` | Галлюцинации не ссылаются на факты, относящиеся к решению | error | анализ контента |
| `V-DETERMINISM` | Две генерации с одним seed дают одинаковый `investigationHash` | error | повтор генерации |

## 2. Солвер решаемости

Модель «идеального, но не всеведущего игрока»: знает правила обнаружения, но не истину.

1. Построить граф обнаружения: узлы — улики/показания; рёбра — предусловия (нужен ключ,
   нужен пароль из другой улики, нужен контакт, нужна локация в часы доступа).
2. BFS от начального состояния → множество достижимых сведений (без учёта времени).
3. Применить `DeductionRules` → установленные утверждения.
4. Проверить `V-CULPRIT-PROVABLE` и `V-UNIQUE`.

## 3. Планировщик по времени

Жадный поиск с лучом (beam search, ширина 8) по действиям игрока с реальными стоимостями и
расписаниями NPC: цель — набрать минимальное покрывающее множество улик. Выход —
`SolutionPath` (последовательность `PlayerAction`), который также используется в E2E-боте (INT-002).

## 4. Ремонт и перегенерация

При ошибке генератор пытается (детерминированно, по подсиду попытки):
1. добавить избыточный след к недоказанному элементу (если правила следов допускают);
2. сдвинуть расписание невиновного персонажа, чтобы дать ему проверяемое алиби;
3. перегенерировать со стадии IncidentSelection с другим кандидатом;
4. перегенерировать с SocialGen.
Максимум 8 попыток. Отчёт содержит причины каждой неудачи.

## 5. Seed sweep

```bash
npm run sweep -- --scenario sanatorium_winter --count 1000 --from 0
```

Выход: `reports/sweep-<scenario>-<from>-<count>.json` + `.md`:

- доля успешных генераций, распределение числа попыток;
- распределение виновников по архетипам и персонажам, энтропия;
- распределение мотивов и типов инцидентов;
- среднее/максимальное время генерации;
- список проваленных seed с первой ошибкой.

**Пороги для CI:** PR — 1000 seed, неудач < 1 %, энтропия виновников ≥ 0,8 · log₂(N); ночной
прогон — 20 000 seed. Проваленные seed добавляются в регрессионный корпус
`packages/validator/regression-seeds.json` и проверяются в каждом PR.

## 6. Мутационные тесты валидатора

Валидатор тестируется на заведомо сломанных расследованиях: удалить ключевую улику, сделать алиби
виновника неопровержимым, поместить персонажа в две локации, добавить цикл предусловий. Каждая
мутация должна ловиться соответствующей проверкой.
