# Передача состояния

Статусы задач находятся в [индексе](../../tasks/INDEX.md). Готовые к захвату задачи показывает
`npm run tasks:ready`.

## Что уже работает

- GEN-014 пропускает контрольные сиды санатория через полный шлюз. Штатный REST из SRV-002
  создаёт дело на seed `1`, `2`, `3`, `6` и возвращает HTTP 201.
- SRV-012 поставляет порты из принятой попытки генерации. Карточка закрыта после переноса
  игрового осмотра и показаний в CNT-013 и ENG-014. Сквозной исход `solved` проверяет INT-002.
- Оболочка телефона и клиент привязки с WebSocket в main. Физическую проверку QR, ручного
  ввода, перепривязки и восстановления проводим в INT-001 с Expo Go на iPhone.
- Android вынесен в MOB-012. Нативная Development Build отложена в INT-007.

## До первого сквозного прогона санатория

1. Подключить проекции и тексты в SRV-010, затем штатный сервер и QR в SRV-013.
2. Завершить Godot-экран привязки GDT-003 и проверить пару устройств в INT-001. Камера и
   результат скана улики идут через MOB-004 и MOB-008.
3. Проверить обязательные физические улики через реальные точки осмотра (CNT-013) и получить
   показания от присутствующих NPC (ENG-014). Открытые решения об источнике окна инцидента и
   включении симуляции перечислены в [реестре вопросов](open-questions.md).
4. Воспроизвести путь действий на сгенерированном деле и проверить бюджет VAL-003, затем
   закрыть серверный сценарий INT-002 до `solved`. Полный плейтест отслеживается в INT-003.

## Перед слиянием

При конфликте генерируемого индекса сохраните изменения обеих веток в карточках, затем выполните
`npm run tasks:index`, `npm run tasks:check` и `npm run docs:check`. Дождитесь проверок итогового
коммита. Для изменений представлений и игрового контракта прогоните Godot-тесты.
